## 3. 為什麼這樣做(決策理由與捨棄的替代方案)

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| 上傳/下載由服務串流轉送 | MinIO 在 `backend` 網路、不曝 port,且全 VM 只有 gateway 持 443,**瀏覽器根本連不到 MinIO** | presigned 直傳(需另開 gateway 路由,且簽章綁 host/path,前綴剝除會破壞簽章) |
| raw body 上傳,不用 multipart | multipart 解析會把大檔落到暫存檔,違反「容器內不寫檔當狀態」 | `multipart/form-data` |
| S3 multipart + 邊收邊算 SHA-256 | 記憶體用量固定在一個 chunk,且雜湊不需第二趟 I/O | 收完再算(大檔要重讀一次) |
| 路由註冊在根路徑 + `root_path` | gateway 以尾斜線 `proxy_pass` **剝掉**前綴 | 自己在路由加前綴(會變成雙前綴 404) |
| 對外網址由設定組出 | TLS 在 gateway 終結,從 request 推導會得到 `http://` | 依賴 `X-Forwarded-Proto` |
| magic bytes 自建簽章表 | 避免 image 多帶 libmagic 系統相依 | `python-magic` |
| HTML/SVG 一律拒收 | 本服務散布可執行檔,讓上傳內容在本網域被瀏覽器執行等同自開 XSS | 只靠 `Content-Disposition` 兜底 |
