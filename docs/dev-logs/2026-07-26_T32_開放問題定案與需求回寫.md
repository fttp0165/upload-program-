### 為什麼這樣做(決策理由與捨棄的替代方案)

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| 容量取 **100 MB** 而非 50 MB | 裁示是「50~100M」的區間;執行檔動輒數十 MB,取下限容易卡住合理用途,取上限較不會馬上要再調 | 取 50 MB;或做成每專案可調 |
| 專案總容量暫定 5 GB | 裁示只給了單檔數字,總量無依據;先沿用原值並列為 Q10,不自行拍板 | 自行決定一個數字不標註 |
| F38 掃毒新開 **M8** 而非塞進 M6 | 「之後再有」是排除在 MVP 外;放進 M6 會讓出場條件永遠達不到 | 留在 M6 標 P2 |
| 稽核表**只存 user_id** | 稽核最容易變成個資紅線的後門;先在需求層就釘死 | 為了好查而存 email/姓名 |
| 最新版以 `published_at` 判定 | 版本號是自由字串,字串排序會讓 `v10` 排在 `v9` 前面 | 依版本號字串排序 |
| 前端補上 F74–F76(上傳、待開通、管理後台) | 裁示的五項是**瀏覽端**;沒有上傳介面與開通介面,使用者與管理員仍得用 curl,M7 的出場條件達不到 | 只做裁示的五項 |
| 新增 T39 前端選型為 T40 的前置 | 子路徑靜態檔是 Cats 平台踩過的坑(PLM 上線 CSS 全 404),選型錯了整個 M7 要重做 | 邊做邊決定 |
