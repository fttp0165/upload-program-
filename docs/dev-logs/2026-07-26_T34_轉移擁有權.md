## 計畫(動工前成文,憲法第二條 2)

### 目標

實作 F16:專案 owner 可把擁有權移交給另一位使用者。
Q2 定案的理由是「**owner 離職就沒人能管該專案**」——沒有這個功能,人員異動後專案會變成孤兒:
沒人能改設定、加成員、刪除。

**本任務是 2026-07-26 定案後的新需求,程式碼尚不存在,因此照憲法第三條走完整 TDD:
先寫會失敗的紅測試,看到它紅,才動實作。**

### 介面設計

`PUT /v1/projects/{slug}/owner`,body `{"user_id": "<uuid>"}`

用 `PUT` 而非 `POST`:擁有權是專案的一個**屬性**,PUT 表達「把它設成這個值」,天然冪等
——重複轉給同一人不該出錯。

### 行為規格(即驗收標準)

| # | 情境 | 預期 |
|---|---|---|
| 1 | owner 轉給另一位已開通使用者 | 200,`owner_id` 改為新人 |
| 2 | 原 owner 的下場 | **自動降為 `maintainer`** —— 不是踢出專案。他通常還要繼續維護,只是不再是負責人 |
| 3 | 新 owner 原本是成員 | 其 `project_member` 列被移除(owner 由 `projects.owner_id` 表示,不重複記) |
| 4 | 重複轉給現任 owner | **200 冪等**,不視為錯誤 |
| 5 | maintainer 嘗試轉移 | **403** —— 只有 owner 能決定繼任者 |
| 6 | viewer / 非成員嘗試轉移 | 403(private 專案對非成員仍是 404) |
| 7 | 轉給不存在的使用者 | 404 |
| 8 | 轉給**未開通**的使用者 | **409** —— 待開通的人連業務 API 都進不來,讓他當 owner 等於製造新的孤兒 |
| 9 | 平台管理員代為轉移 | 200 —— 這正是 owner 已離職時的救援路徑 |

## 結果(完工後補記)

### 紅 → 綠(第三條的完整流程,這次是真的)

**先寫測試,跑,看到它紅:**

```
$ pytest tests/test_ownership.py -q
FAILED test_owner可把擁有權轉給他人           - assert 404 == 200
FAILED test_原owner自動降為maintainer而非被踢出 - KeyError
FAILED test_新owner原本是成員時不留重複的成員列  - AssertionError
FAILED test_重複轉給現任owner是冪等的          - assert 404 == 200
FAILED test_maintainer不能轉移擁有權           - assert 404 == 403
FAILED test_非成員不能轉移擁有權               - assert 404 == 403
FAILED test_不得轉給未開通的使用者             - assert 404 == 409
FAILED test_平台管理員可代為轉移               - assert 404 == 200
8 failed, 1 passed
```

> ⚠️ 那 1 個「passed」是 `test_轉給不存在的使用者回404`——**因為錯誤的理由通過**:
> 端點不存在時路由本身就回 404。實作後我補上 `assert "使用者" in detail`,
> 讓它只能因正確理由通過。這種假通過很容易矇混過去,值得記一筆。

### 為什麼這樣做(決策理由與捨棄的替代方案)

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| 用 `PUT .../owner` 而非 `POST .../transfer` | 擁有權是專案的一個**屬性**,PUT 表達「設成這個值」,天然冪等——重複轉給同一人不該出錯 | `POST /transfer`(要另外處理重複呼叫) |
| 原 owner **降為 maintainer** 而非踢出 | 交棒的人通常還要繼續維護,只是不再是負責人。踢出會讓他連 private 專案都看不到 | 直接移除;或降為 viewer |
| 新 owner 的成員列**刪除**而非改成 owner | 擁有權由 `projects.owner_id` 表示;兩邊都記會出現同一人兩列、且可能不一致 | 保留成員列並設 role=owner |
| 轉給未開通者回 **409 而非 400** | 這不是「請求格式錯」,而是「現在的狀態不允許」——待開通者連業務 API 都進不來,讓他當 owner 等於製造下一個孤兒 | 400;或允許並期待日後開通 |
| 平台管理員可代為轉移 | **這正是 F16 存在的理由**:owner 已離職就不可能自己來按 | 只有 owner 能操作(那孤兒專案就永遠是孤兒) |
| log 記 `performed_by_admin` | 管理員代為轉移是敏感操作,日後接稽核(T38)時這欄直接可用 | 不記 |
