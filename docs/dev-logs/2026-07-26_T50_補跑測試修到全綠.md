## 計畫(動工前成文,憲法第二條 2)

### 目標

`tests/` 下的四個測試檔自寫成以來**從未執行過**(欠項 A1)。憲法第三條 5 明訂
「測試全綠指實際跑過並看到綠燈」,因此 T06–T24 目前全部只能標 ⚠️。

本任務要:**實際執行測試 → 修到全綠 → 貼出證據**,讓那批 ⚠️ 任務具備結案的第一個條件。

### 影響範圍

| 類型 | 檔案 |
|---|---|
| 可能修改 | `app/` 下任何被測出缺陷的模組 |
| 可能修改 | `tests/` 下寫錯的測試(**僅限測試本身寫錯**,見下方紅線) |
| 新增 | 若發現既有測試涵蓋不到的缺陷,補測試 |
| 不動 | 文件、容器與部署設定(除非測試逼出設定缺陷) |

**對現有資料的影響:🟢 不動資料。** 測試一律使用 SQLite 暫存檔與記憶體版物件儲存,
不接觸任何 PostgreSQL 或 MinIO 實例。

### 🔴 本任務的紅線

**不得為了讓測試變綠而弱化斷言或刪測試。**
測試紅燈有兩種可能:(a) 程式有缺陷 → **修程式**;(b) 測試本身寫錯 → 修測試,
但必須在日誌中逐項說明「為什麼是測試錯而不是程式錯」。
把 `assert x == 201` 改成 `assert x in (201, 409)` 這種「調寬預期」的做法,一律視為違反本任務。

### 驗收標準

1. `pytest` 全數通過,無 failed、無 error;跳過的測試必須逐一說明理由
2. 每一個紅燈都有記錄:症狀、根因、修法、判定是程式錯還是測試錯
3. 修 bug 處依第五條在程式碼中註明**根本原因**,避免後人改回去
4. `ruff check` 通過(lint 是 CI 的一部分,先在本機清乾淨)
5. 任務表中 T06–T24 的 ⚠️ 依實際情況更新;欠項 A1 結案
6. 貼出實際執行輸出作為證據(第三條 5)

### 回滾方式

程式碼變更以 `git revert` 回復;測試與文件同理。
本任務不動資料庫、不動部署,無需資料層回滾程序。

### 修掉的紅燈(逐項根因)

| # | 症狀 | 根因 | 判定 | 修法 |
|---|---|---|---|---|
| 1 | 連 import 都失敗,`ValidationError: 11 errors` | `app/main.py` 模組層有 `app = create_app()`,**光是 import 就要求完整 .env**。測試、alembic、任何想借工廠函式的工具全部中彈 | **程式錯** | 進入點移到 `app/asgi.py`;`app/main.py` 只留工廠函式,import 無副作用。Dockerfile CMD 同步改 `app.asgi:app` |
| 2 | 每個錯誤回應都先炸在錯誤處理器裡 | `problems.py` 直接呼叫 `get_settings()`,等於**每產生一個錯誤就重讀環境變數**;真正的錯誤反而被蓋掉 | **程式錯** | 改為優先取 `request.app.state.settings`,拿不到才回退 |
| 3 | 所有需要 DB 的端點一律 422 `query.request Field required` | `db.py` 的 `get_session(request)` **少了型別註解**,FastAPI 因此把它當成查詢參數 | **程式錯** | 補上 `request: Request`。註解在 FastAPI 不是風格問題,它決定參數從哪裡取 |
| 4 | 建立版本回 500,`MissingGreenlet` | `Release.artifacts` 用預設 lazy load,序列化時才碰它 → async session 下觸發同步 IO | **程式錯** | 改 `lazy="selectin"`。版本幾乎總是連檔案一起呈現,也讓這類漏載入不再可能 |
| 5 | `test_token無效回401` 拋 `UnicodeEncodeError` | 測試把中文塞進 `Authorization` 標頭;**HTTP 標頭值必須是 ASCII**,炸在客戶端、請求根本沒送出 | **測試錯** | 假 token 改 ASCII。**斷言(401)一字未動** |

> 🔴 全程未曾為了讓測試變綠而放寬任何斷言。第 5 項是唯一的「測試錯」,
> 錯的是測試資料的字元集,不是預期行為。

跑綠之後我檢查覆蓋範圍,發現**兩塊契約義務完全沒有被測到**,當場補上:

| 檔案 | 補了什麼 | 為什麼非補不可 |

| `tests/test_token_verify.py`(15 條) | 用**當場產生的 RSA 金鑰**驗真章:RS256 通過、**HS256 拒**、**alg=none 拒**、過期拒、**±30 秒容忍**、**kid 輪替新舊並存**、未知 kid 拒、別人的 aud 拒、iss 不符拒、缺 sub 拒、nonce 不符拒、竄改簽章拒、azp 回退、JWKS 未就緒回 401 而非 500 | 其他測試全走 `FakeOidc` 繞過驗章,**`app/oidc.py` 真正的驗證邏輯一行都沒被測到**——而那正是 SSO 契約 §3.2 的核心義務 |
