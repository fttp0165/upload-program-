## 計畫(動工前成文,憲法第二條 2)

### 目標

實作 F70:全站共用的導航列與版型骨架。這是 M7 其餘五項(T41–T45)的地基——
它們都只是往 `{% block content %}` 裡填東西。

驗收標準寫的是:**全站共用;子路徑下所有連結與靜態檔皆正確,無 404。**
後半句才是本任務的真正難點。

### 🔴 子路徑:這裡錯了就是 PLM 的坑

拓撲(接入指南):gateway 以尾斜線 `proxy_pass http://upload-program:8080/;`
**剝掉前綴**後轉發。所以:

| | 瀏覽器看到的網址 | 本服務收到的路徑 |
|---|---|---|
| 首頁 | `https://host/upload/` | `/` |
| 樣式表 | `https://host/upload/static/app.css` | `/static/app.css` |

**頁面裡寫的連結是給瀏覽器用的,所以必須帶前綴**;路由註冊則一律用不帶前綴的路徑。
兩者搞混就是 PLM 出過的 404 事故(決策文件 §6.2:框架自動剝前綴、gateway 卻保留前綴的錯配)。

**做法:一個 `web_url(settings, path)` 助手,產出 root-relative 的網址**
(`/upload/static/app.css`),模板裡所有 `href`/`src`/`action` 都經過它。

為什麼是 root-relative 而不是絕對網址:絕對網址要組 scheme 與 host,而
**TLS 在 gateway 終結,從 request 推導會得到 `http://`**。root-relative 讓瀏覽器
沿用目前的 scheme 與 host,直接繞開這個問題。絕對網址只留給非絕對不可的地方
(OIDC redirect_uri,已在 `config.py` 處理)。

> 不使用 `request.url_for()`:它會產生絕對網址,又要面對上面那個 scheme 問題。
> 我們也不使用 WhiteNoise —— 決策文件 §6.2 已載明,那正是 PLM 錯配的來源。

### 導航列的內容:刻意少做一項

F70 列的是「站名、搜尋框、**建立專案**、登入狀態與登出」。

本任務**不做「建立專案」入口**——建立專案的頁面要到 T44 才存在,現在放上去就是一條
懸空連結,直接違反驗收標準的「無 404」。改為:

- T40 交付 站名、搜尋框、登入狀態與登出
- **「建立專案」入口寫進 T44 的驗收標準**,與它的頁面同時上線

寧可少一項而且說清楚,也不要為了讓表格打勾而放一條會 404 的連結。

### 登入狀態:頁面不得因為沒登入就 401

導航列要顯示「登入」或「使用者名稱 + 登出」。這需要一個**不會拋 401 的身分相依**
(`optional_identity`)——網頁跟 API 不同,匿名訪客該看到登入按鈕,不是一頁錯誤。

🔴 顯示用的名字**來自 IdP 的 claims,不從業務庫讀**(業務庫只存 `sub`,契約 §6.1
的姓名快取是 PLM 的具名特例,本專案不繼承)。這件事在 `/v1/me` 已經是這樣做,
導航列沿用同一條路。

### 順帶收掉 T47 的兩項遺留

| T47 遺留 | 本任務處理 |
|---|---|
| #1 錯誤頁沒有「回首頁」連結 | 導航列即是,`error.html` 繼承 base 後自動有 |
| #2 錯誤頁未 extend 共用版型、CSS 內嵌 | 改為繼承 `base.html`,CSS 收斂到 `static/app.css` |

### 加上 CSP:現在是最便宜的時機

本服務散布可執行檔,紅線寫著「絕不讓上傳內容在本服務網域被瀏覽器執行」。
`SecurityHeadersMiddleware` 目前有 `nosniff` / `X-Frame-Options` / `Referrer-Policy`,
**沒有 CSP**。現在全站零 JS、CSS 也正要搬進 `static/`,是導入嚴格 CSP 成本最低的時刻;
等 T44 寫了上傳 JS 再補,就得回頭改一輪。

```
default-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'
```

`style-src` 落在 `default-src 'self'` 底下 → **內嵌 `<style>` 會被擋**,
這正好逼著 CSS 一定要搬進 `static/`(順便解掉 T47 遺留 #2)。
T44 的上傳 JS 也必須是外部檔案而非 inline —— 那本來就是比較好的寫法。

> 錯誤頁的 CSS 搬到外部檔案後,若靜態檔服務本身壞掉,錯誤頁會沒有樣式但**仍可讀**。
> 這是可接受的降級——內容才是重點。

### 檔案配置(依決策文件 §6.1)

```
app/templates/base.html     版型骨架 + 導航列
app/templates/home.html     首頁(本任務只有骨架,內容由 T41 填)
```

### 行為規格(即驗收標準)

| # | 情境 | 預期 |
|---|---|---|
| 1 | `GET /` | 200,`text/html`,含站名 |
| 2 | 導航列 | 含站名、搜尋框、登入/登出入口 |
| 3 | 🔴 頁面內所有 `href`/`src`/`action` | **一律帶 `api_prefix`**,一個都不能漏 |
| 4 | 🔴 頁面內連結 | **沒有任何一個以 `http://` 或 `https://` 開頭**(不從 request 推導) |
| 5 | `web_url()` 純函式 | `api_prefix` 為空時產出 `/static/app.css`,不得是 `//static/...` |
| 6 | `GET /static/app.css` | 200,`content-type` 為 `text/css` |
| 7 | 匿名訪客開首頁 | **200 而非 401**,導航列顯示「登入」 |
| 8 | 已登入者開首頁 | 導航列顯示 IdP claims 裡的名字與「登出」 |
| 9 | 🔴 顯示名稱的來源 | 換一個 claims 不同的 token,頁面跟著變——證明**不是**從業務庫讀 |
| 10 | 錯誤頁 | 繼承 base,含導航列 |
| 11 | CSP | 回應含 `Content-Security-Policy`,且 `default-src 'self'`、`object-src 'none'` |
| 12 | 憲法第四條 | 頁面與 CSS 皆無 `prefers-color-scheme: dark`、無外部資源網址 |
| 13 | XSS | 使用者可控內容仍逸出(T47 的既有測試必須維持綠) |

> 第 3、4 條是本任務的核心,要**解析 HTML 抓出所有連結**逐一檢查,
> 而不是抽驗幾個字串——漏掉一個就是一次 404 事故。

## 結果(完工後補記)

### 紅 → 綠

```
先寫 15 條測試 → 13 failed / 2 passed
實作後        → 15 passed(過程中追加 1 條,共 16);全套 179 → 195 passed;lint 全過
```

兩條一開始就綠的:一條是 T47 的逸出紅線(**回歸測試**,換版型後必須依然成立),
另一條是「頁面內不得出現絕對網址」——當時頁面根本沒有連結,所以它是**當下空過**的。
不過同組的「所有連結都要帶前綴」有 `assert found` 擋著,兩條合起來不會一起空過。

### 🐛 這次抓到一個會在正式環境炸掉的真缺陷

`test_靜態樣式表可取得` 紅燈,查下去是**子路徑的坑真的出現了**:

```
GET /static/app.css          → 404      ← gateway 剝掉前綴後,我們實際會收到的路徑
GET /upload/static/app.css   → 200
```

根因:本 app 設了 `root_path=api_prefix`(讓 `/docs` 產生正確網址),
而 Starlette 的 **`Mount` 會依 root_path 再剝一次前綴**(`get_route_path`)。
gateway 已經剝過一次,於是傳給 `StaticFiles` 的子路徑多了一層,檔案找不到。
一般 `Route` 沒有這個二次剝除,所以 `/v1/*` 全部正常——**只有 Mount 中招**。

> 這正是決策文件 §6.2 警告的那一類錯配(PLM 的 404 事故),**只是方向相反**:
> 那次是「框架剝、gateway 沒剝」,這次是「gateway 剝了、框架又剝一次」。
> 而它會在本機開發(沒有 gateway、沒設前綴)完全正常,**只在正式環境全站樣式 404**。

修法:改用一般路由 `GET /static/{path:path}`,內部仍委派
`StaticFiles.get_response()`——它的 `lookup_path()` 會 realpath 後檢查 commonpath,
擋掉 `../` 路徑逃逸,這種安全檢查不該自己重寫。根因已寫成 `web.py` 的註解。

因為安全責任變成我們的,**追加了一條路徑逃逸測試**,並用「直接 `FileResponse(dir / path)`」
的錯誤寫法實測它非空測:

```
FileResponse(static_dir / path)          →  FAILED(RuntimeError,/etc/passwd 那條)
_static.get_response(path, scope)        →  passed
```

### 測試抓到我自己的註解

`test_樣式表為light且無外部資源` 紅燈,原因是 `app.css` 的**註解裡**寫了
「不使用 `prefers-color-scheme` 自動切深色」——測試用字串比對,連註解一起抓到。

選擇**改註解而不是放寬測試**:嚴格的字串比對能讓「哪天有人手滑加了深色模式」當場紅燈,
這個價值高於註解的措辭。已在 CSS 檔頭註明本檔刻意不出現那個字串及其原因。

### 為什麼這樣做(決策理由與捨棄的替代方案)

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| **`web_url()` 產 root-relative 而非絕對網址** | 絕對網址要組 scheme,而 TLS 在 gateway 終結,從 request 推導會得到 `http://`;root-relative 讓瀏覽器沿用當前 scheme/host,直接繞開 | `request.url_for()`(會產生絕對網址) |
| **靜態檔用一般路由而非 `app.mount`** | `root_path` + `Mount` 會二次剝前綴 → 正式環境全站樣式 404(見上) | `app.mount("/static", StaticFiles(...))` |
| **仍委派 `StaticFiles.get_response()`** | 它的 `lookup_path()` 有 realpath + commonpath 的逃逸防護;自己寫 `FileResponse(dir / path)` 就是路徑穿越漏洞(已實測) | 自行組路徑回 FileResponse |
| **共用一個 Jinja2 Environment(`templating.py`)** | 錯誤頁與其他頁面必須同版型、同 autoescape 設定;兩份 Environment 遲早長歪 | problems.py 與 web.py 各自建 |
| **`optional_identity` 不拋錯** | 網頁跟 API 不同:匿名訪客該看到登入按鈕,不是一頁 401 | 網頁也用 `CurrentUser` |
| **CSP 在 T40 導入** | 當時全站零 JS、CSS 正要搬進 static/,是成本最低的一刻;等 T44 寫了上傳 JS 再補就得回頭改一輪。`default-src 'self'` 擋掉內嵌樣式,正好逼著 CSS 一定要外部化 | 留到 T44 或不做 |
| **導航列不放「建立專案」** | 那個頁面要到 T44 才存在,現在放就是一條會 404 的連結,直接違反本任務的驗收標準 | 先放連結、之後補頁面 |
| **F70 標 ⚠️ 而非 ✅** | F70 列的項目沒有全數交付。寧可少打一個勾,也不要讓表格與現實不符 | 標 ✅ 反正差不多 |
