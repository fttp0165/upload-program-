## 計畫(動工前成文,憲法第二條 2)

### 目標

把 T40 留下的首頁骨架填成真的首頁:**專案列表 + 關鍵字搜尋 + 標籤篩選 + 分頁**。
導航列的搜尋框在 T40 就已經把 `?q=` 送到首頁了,本任務讓它真的查得到東西。

驗收標準:**只顯示當事人看得到的專案;分頁可用。**

### 🔴 可見性不得因為換到網頁就鬆掉

這是本任務唯一的紅線。`GET /v1/projects` 的可見性規則(internal 全站可見、
private 只有成員與 owner、admin 全部看得到)已經寫在 `projects.list_projects` 裡,
**網頁不能自己再寫一份**——兩份查詢遲早會分岔,而分岔的後果是 private 專案外洩。

**做法:把查詢抽成 `app/queries.py` 的 `query_projects()`,API 與網頁共用。**
這與 T35(下載回應)、T37(下載計數)、T47(錯誤協商)是同一個模式:
**同一件事只能有一條路。**

抽出來的東西只有「條件組裝 + 分頁查詢」,回傳 `(total, rows)` 的 ORM 物件;
`ProjectOut` 的組裝仍留在 API 端(網頁直接用 ORM 物件即可,不需要多一層轉換)。

### 未登入與待開通:頁面要說人話

`list_projects` 用的是 `CurrentUser`(未登入 401、未開通 403)。網頁不能這樣:

| 狀態 | 首頁顯示 |
|---|---|
| 匿名 | 「請先登入以瀏覽專案」+ 登入按鈕(**不是 401**) |
| 待開通 | 待開通指引(F75 的完整頁面是 T45,這裡先給同一段文案) |
| 已開通 | 專案列表 |

待開通的文案**直接取 `problems.pending_activation().detail`**,不另外寫一份中文——
兩份文案遲早會不一致,而使用者會同時從 API 與網頁看到它。

### 分頁:連結要自己組,不能在模板裡拼

上一頁/下一頁的連結要帶著目前的 `q` 與 `tag`。這些是使用者輸入,
**必須 URL 編碼**(`urlencode`),否則 `?q=a&b=c` 這種輸入會塞進額外參數,
含 `#` 的輸入會把後面整段吃掉。

在 Python 端用 `urlencode` 組好再傳給模板,而不是在 Jinja 裡拼字串:
模板的 autoescape 管的是 **HTML 逸出**,不管 **URL 編碼**,兩者是不同的問題,
在模板裡拼很容易只做到一半。

> 已知的雙重防護:`urlencode` 負責 URL 語意,autoescape 負責 HTML 語意,
> 兩層都要有。測試會用 `"><script>` 這種輸入同時驗兩件事。

### 標籤要可點

列表上每個標籤都是一個連結,指向 `?tag=<標籤>`(F42 的瀏覽入口)。
標籤本身已在寫入時正規化過(小寫、無空白),但**仍要 URL 編碼**——中文標籤必然需要。

### 版面

沿用 T40 的 `app.css`,新增專案卡片與分頁的樣式。維持 light、零外部資源。

### 行為規格(即驗收標準)

| # | 情境 | 預期 |
|---|---|---|
| 1 | 匿名訪客開首頁 | 200,顯示登入提示,**不列出任何專案** |
| 2 | 待開通者開首頁 | 200,顯示待開通指引(與 API 同一段文案) |
| 3 | 已開通者開首頁 | 列出看得到的專案(名稱、slug、摘要、標籤) |
| 4 | 🔴 private 專案 | **不出現在非成員的首頁**;成員則看得到 |
| 5 | 🔴 網頁與 API 的可見性一致 | 同一個非成員,`GET /` 與 `GET /v1/projects` 看到的專案集合相同 |
| 6 | `?q=關鍵字` | 只列出符合的專案 |
| 7 | `?tag=python` | 只列出帶該標籤的專案 |
| 8 | 標籤連結 | 指向 `?tag=…`,帶路徑前綴,且經過 URL 編碼(含中文標籤) |
| 9 | 分頁 | 超過一頁時有「下一頁」;`?offset=` 生效;最後一頁沒有「下一頁」 |
| 10 | 分頁連結 | 帶著目前的 `q` 與 `tag` |
| 11 | 空結果 | 顯示空狀態文案,不是一片空白 |
| 12 | 🔴 `q` 含 `"><script>` | HTML 逸出 **且** URL 編碼,不得破壞版面或連結 |
| 13 | 所有連結 | 仍帶路徑前綴、仍無絕對網址(T40 的紅線維持) |

## 結果(完工後補記)

### 紅 → 綠

```
先寫 13 條測試 → 10 failed / 3 passed
實作後        → 13 passed;全套 195 → 208 passed;lint 全過
```

3 條一開始就綠的是 T40 的紅線回歸(連結帶前綴、無絕對網址、逸出)加上
「匿名訪客不該看到專案」——最後這條在當時是空過的(頁面根本沒列專案),
但它的同組測試「已開通者看到專案卡片」保證了實作後它會有意義。

### 兩條關鍵測試都實測過非空測

這次有兩個地方最容易寫出「永遠會過」的測試,所以都把實作改壞跑一次:

| 改壞的地方 | 結果 |
|---|---|
| 網頁自己寫一份**沒有可見性過濾**的查詢 | `test_private專案不出現在非成員的首頁`、`test_網頁與API看到的專案集合一致` **雙雙變紅** |
| `urlencode` 換成 `"&".join(f"{k}={v}")` | `test_標籤是可點的連結且經過URL編碼` **變紅** |

第一項尤其重要:它證明的不只是「現在對」,而是**日後有人在網頁另寫一份查詢時會當場紅燈**。

### 為什麼這樣做(決策理由與捨棄的替代方案)

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| **可見性查詢抽成 `queries.query_projects()`** | 兩份查詢遲早會分岔,而分岔的後果是 **private 專案外洩**。這與 T35 / T37 / T47 是同一個模式:同一件事只能有一條路 | 網頁自己寫一份查詢 |
| **回傳 ORM 物件而非 `ProjectOut`** | 網頁直接用 ORM 物件即可;`ProjectOut` 帶著 `my_role`/`quota_bytes` 這些要逐筆查詢或算的欄位,首頁用不到,強塞只是浪費 | 共用函式直接回 `ProjectOut` |
| **`urlencode` 在路由端做,不在模板拼** | autoescape 管 HTML 語意、`urlencode` 管 URL 語意,是兩件事;在 Jinja 裡拼很容易只做到一半 | 模板裡 `?q={{ q }}&offset={{ ... }}` |
| **待開通文案取自 `problems.pending_activation().detail`** | 兩份中文遲早會不一致,而使用者會同時從 API 與網頁看到它 | 模板裡另寫一段 |
| **未登入/待開通不回錯誤,但也不查詢** | 網頁該顯示登入按鈕而不是 401;但「不回錯誤」不等於「可以少過濾」——只有已開通者才走到查詢 | 一律查詢再靠模板決定顯不顯示 |
| **每頁 20 筆,與 API 預設一致** | 兩邊不同會讓「API 第二頁」與「網頁第二頁」指的不是同一批資料,除錯時很困惑 | 網頁另設頁面大小 |

### 對現有資料的實際影響

**🟢 不動資料。** 純呈現層,無 migration。
`list_projects` 是純重構,既有 7 條專案測試維持全綠(憲法第三條 4 的安全網)。
