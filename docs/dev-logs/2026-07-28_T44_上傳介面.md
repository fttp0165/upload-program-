## 計畫(動工前成文,憲法第二條 2)

### 目標

驗收標準:**不需 curl 即可完成一輪上傳與發布**;XHR PUT 並顯示上傳進度與失敗提示;
**導航列補上「建立專案」入口**(T40 刻意延後的那一項);JS 須為外部檔案。

這是 **M7 出場條件的最後一塊**——「使用者不需 curl 即可完成一輪上傳與下載」,
下載那半在 T42 就通了,上傳這半靠本任務。

### 完整的一輪:四個步驟、三個頁面

```
導航列「建立專案」
   ↓  POST 表單(urlencoded)
/projects/new            建立專案
   ↓
/projects/{slug}         專案頁 →「建立新版本」
   ↓  POST 表單
/projects/{slug}/releases/new    建立 draft 版本
   ↓
/releases/{id}/upload    上傳頁:XHR PUT 傳檔 + 進度條 → 發布按鈕
   ↓  POST 表單
專案頁(已發布)
```

### 為什麼只有「傳檔」需要 JS

HTML `<form>` 只能發 **GET / POST**,且只能送 urlencoded 或 multipart,
**發不出 raw body 的 PUT**(決策文件 §5.1)。

所以:

| 動作 | 做法 |
|---|---|
| 建專案、建版本、發布、刪檔 | **純 HTML 表單 POST**,零 JS |
| **傳檔** | XHR `PUT`,監聽 `upload.onprogress` |

不新增 multipart 端點——那等於把「不落暫存檔」的設計退回去(決策文件 §5.1 已定案)。

**沒有 JS 的人仍能做完前三步**,只有傳檔那一步需要 JS。這是刻意的漸進增強。

### 🔴 JS 必須是外部檔案

CSP 是 `default-src 'self'`(T40),inline script 一律被擋。
所以 `app/static/upload.js`,不是 `<script>` 內嵌。

T51 已經放了一條原始碼守門:`static/` 與 `templates/` 中**不得出現
`localStorage` / `sessionStorage`**(契約 §4.10:同源之下瀏覽器儲存空間全平台可讀)。
本任務是第一次真的寫 JS,**那條守門從今天起開始擋人**——這正是它的用途。

上傳靠 **session cookie**(HttpOnly),JS 完全碰不到 token,也不需要碰。

### 🔴 CSRF:決策文件說「日後新增 POST 表單時需另評估」,現在就是那個時候

決策文件 §6.5 寫著:

> session cookie 已是 `HttpOnly` + `Secure` + **`SameSite=Lax`**,跨站送出的
> PUT / PATCH / DELETE 不會帶上 cookie,CSRF 風險已大幅降低。
> **若日後新增以 `POST` 表單送出的狀態變更,需另評估是否加 CSRF token。**

**本任務就是新增 POST 表單的狀態變更**,所以現在評估:

`SameSite=Lax` 的語意是「只在**頂層 GET 導覽**時送出 cookie」。
跨站的 `<form method="post">` 送出時**不會帶 cookie** → 請求會被當成未登入 →
擋下。這對 POST / PUT / DELETE 都成立。

**結論:不加 CSRF token。** 理由:
- `SameSite=Lax` 已在瀏覽器層擋掉跨站 POST 帶 cookie
- 加 token 需要在每個表單埋一個值、在伺服器端存對照,對這個規模是額外的活動零件
- **但要寫一條測試釘住 `SameSite=Lax`** ——這個結論完全建立在那個屬性上,
  哪天有人改成 `None`,防護就沒了而且沒人會發現

這是**有條件的決定**:條件寫成測試,條件消失時測試會紅。

### 權限:頁面不得比 API 寬鬆

| 頁面 | 需要 |
|---|---|
| `/projects/new` | 已開通(任何人都能建自己的專案) |
| `/projects/{slug}/releases/new` | **maintainer 以上** |
| `/releases/{id}/upload` | **maintainer 以上** |

一律走既有的 `require_project_role()`,不另寫判斷。
🔴 非 maintainer 開上傳頁 → 走既有規則(private 非成員 404、成員但權限不足 403)。

### 導航列「建立專案」

T40 刻意延後的那一項,現在頁面存在了,補上。
**只對已開通者顯示**——匿名/待開通者看到它只會撞牆。

### 錯誤提示

表單送出失敗(slug 重複、版本號重複)時要**回到表單並顯示訊息**,
不是丟一頁錯誤讓使用者重打。XHR 失敗則在頁面上顯示,並保留重試的機會。

### 🐛 兩個真 bug,都只會在某一條路徑上安靜地壞掉

**1. 路由順序:`/projects/new` 被 `/projects/{slug}` 吃掉**

我把新路由**附加在檔案末尾**,而 `/projects/{slug}`(T42)註冊在前面。
FastAPI 依註冊順序比對,於是 `"new"` 被當成 slug → `get_project()` 找不到 → **永遠 404**。

沒有任何警告。修法是把兩條 `/projects/new` 移到動態路由之前,並在該處留下註解
——**路由順序是有意義的**,下一個加靜態路由的人需要知道。

**2. `MissingGreenlet` 第三次變形**

slug 重複 → `session.rollback()` → **session 裡所有 ORM 物件過期** →
模板算繪(同步)讀 `identity.user.is_active` 觸發 lazy load → 炸。

這是 T50(`Release.artifacts` 序列化時 lazy load)那個家族的第三次出現。
共同的形狀:**在沒有 async 上下文的地方碰到過期的 ORM 屬性**。
修法是在還有 async 上下文時 `await session.refresh(...)` 取回來。

> 值得記住的是**觸發它的新途徑**:`rollback()` 會讓所有物件過期。
> 任何「回滾之後還要算繪頁面」的流程都會踩到——而錯誤訊息完全不會提到 rollback。

### 🔴 CSRF 評估(決策文件 §6.5 要求的)

決策文件寫著「若日後新增以 POST 表單送出的狀態變更,需另評估是否加 CSRF token」。
本任務就是那個時候,評估結果:

**不加 CSRF token。** `SameSite=Lax` 只在**頂層 GET 導覽**時送出 cookie,
跨站 `<form method="post">` 不會帶 cookie → 被當成未登入 → 擋下。

但這個結論**完全建立在那個 cookie 屬性上**,所以寫了一條測試釘住它
(`test_session_cookie為SameSite_Lax`)。哪天有人改成 `None`,防護就沒了
而且沒有人會發現——**有條件的決定,條件要寫成測試。**

### 做了什麼

| 檔案 | 異動 |
|---|---|
| `app/routers/web.py` | 六條路由:建專案(GET/POST)、建版本(GET/POST)、上傳頁、發布 |
| `app/templates/project_new.html` / `release_new.html` / `upload.html` | **新檔** |
| `app/static/upload.js` | **新檔**:XHR PUT + 進度 + 失敗提示 |
| `app/templates/base.html` | 「建立專案」入口(只對已開通者)、`{% block scripts %}` |
| `app/templates/project.html` | 「建立新版本」入口 |
| `requirements.txt` | `python-multipart`(**只解析表單欄位,檔案上傳仍是 raw body PUT**) |
| `tests/test_web_upload.py` | 18 條 |

### 為什麼這樣做

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| **只有傳檔用 JS** | HTML 表單發不出 raw body PUT;其餘四個動作純表單就夠。沒有 JS 的人仍能做完前三步 | 整個流程都用 JS |
| **不新增 multipart 上傳端點** | 那等於把「不落暫存檔」的設計退回去(決策文件 §5.1 已定案) | 給表單一個 multipart 端點 |
| **端點與上限放進 `data-*`** | JS **不知道路徑前綴是什麼**,自己拼就是 PLM 那類 404 事故 | JS 裡寫死路徑 |
| **XHR 帶 `Accept: application/json`** | 讓錯誤回應走 problem+json 而非 HTML(T47 的協商規則),JS 才解析得出 `detail` | 用預設 Accept |
| **前端也擋一次檔案大小** | 省得傳完 100 MB 才被退回。**但那只是體驗,不是防線**——伺服器端仍會再擋 | 只靠伺服器擋 |
| **`python-multipart` 只用於表單欄位** | 已在 requirements 註明,免得日後有人以為我們改用 multipart 傳檔 | — |
| **不加 CSRF token** | `SameSite=Lax` 已在瀏覽器層擋掉;條件已寫成測試 | 每個表單埋 token + 伺服器端對照 |
