## 計畫

### 目標

契約 §7 冒煙第 1 項:「未登入開你的 App → 302 到登入頁」。

我方在 T40–T42 一路採「網頁顯示登入按鈕,不是一頁錯誤」,與此字面衝突。
**2026-07-28 Benny 裁示:深層頁 302、首頁留落地頁。**

| | 行為 |
|---|---|
| 深層頁(`/projects/*`) | **302 到 `/auth/login`**,帶 `next` 導回原頁 |
| 首頁(`/`) | 保留落地說明頁——它承擔「這是什麼系統、找誰開通」的功能 |

### 🔴 轉址不得洩漏專案是否存在

T42 花了力氣做到的結構保證(匿名一律不查詢)**不能因為改成轉址就破功**。

陷阱與 T42 完全一樣,只是換了個外衣:如果先查專案、查不到就 404、
查得到才 302,那**「有沒有轉址」本身就是答案**。

做法不變:**在查詢之前就決定要不要轉**。存在的 private 專案與不存在的 slug
必須導到一模一樣的地方(只有 `next` 不同,而 `next` 就是使用者自己打的網址)。

### 待開通者不轉址

已經登入的人再送去 IdP 只會轉一圈回來。待開通者要的是**指引**,不是轉址。

### 行為規格

| # | 情境 | 預期 |
|---|---|---|
| 1 | 未登入開專案頁 / 歷史頁 | 302 到 `/«PREFIX»/auth/login` |
| 2 | 302 的 `next` | 導回原本要去的頁 |
| 3 | 首頁未登入 | **200 落地頁**,不轉址 |
| 4 | 🔴 存在 vs 不存在的專案 | **導到一模一樣的地方** |
| 5 | 待開通者 | 200 指引,不轉址 |
| 6 | API 未認證 | **仍是 401 + problem+json**,不受影響 |
| 7 | 🔴 `next` | 只能是站內相對路徑(擋開放轉址) |

### 影響範圍

新增 `tests/test_web_login_redirect.py`;修改 `app/routers/web.py`。

## 結果

### 紅 → 綠

```
先寫 8 條測試 → 5 failed / 3 passed
實作後       → 8 passed;全套 259 → 267 passed;lint 全過
```

3 條一開始就綠的是「**不該**轉址」那組(首頁落地頁、待開通者、API 維持 401)。
它們釘的是**轉址不得越界**——而實作轉址時最容易犯的錯正是轉太多。

### 🔴 不洩漏存在:再次以「把實作改壞」實測

把判斷順序改回「先查再判身分」:

```
project = await get_project(session, slug)   # 先查
if identity is None: return 302              # 再判身分
```

```
先查再判身分  →  FAILED test_302不洩漏專案是否存在
              (存在的專案 302、不存在的 404 —— 轉址與否就是答案)
查詢前先決定  →  8 passed
```

**這是同一個陷阱第二次出現**(T42 是「200 vs 404」,這次是「302 vs 404」)。
外衣換了,本質沒變:**任何依身分而異的分支,都必須在碰資料庫之前就決定完。**

### 做了什麼

| 檔案 | 異動 |
|---|---|
| `app/routers/web.py` | `_login_redirect()`;專案頁與歷史頁的匿名分支改為 302 |
| `tests/test_web_login_redirect.py` | **新檔** 8 條 |

### 為什麼這樣做

| 決策 | 理由 | 捨棄的方案 |
|---|---|---|
| **深層頁 302、首頁落地頁** | Benny 裁示。深層頁沒有說明功能,直接送去登入是最短路徑;首頁需要說明「這是什麼、找誰開通」 | 全部 302 / 全部落地頁 |
| **在查詢之前決定** | 否則轉址與否本身洩漏專案存在(同 T42) | 先查再判 |
| **待開通者不轉址** | 他已經登入了,再送去 IdP 只會轉一圈回來 | 一律轉址 |
| **`next` 交給既有的 `_safe_next()` 再驗一次** | 開放轉址防護已經在 `auth.login()` 裡;不重寫第二份 | 在 web.py 再驗一次 |
