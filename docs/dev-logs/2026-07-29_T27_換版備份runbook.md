## 結果(完工後補記,2026-07-29 04:25)

### 異動檔案

如影響範圍所列,無出入。`render_docs.py --check` 通過,HTML 已同步產生。

### 為什麼這樣做(超出綱要的決定)

1. **演練段寫成「證據表」而不是敘述文**:演練的目的不是「做過」而是
   「留下可查證的做過」。每一步都指定要留存什麼輸出(列數、SHA-256、
   冒煙 status),日後翻出來就是 T27 轉 ✅ 的依據——避免「演練了,
   但只剩一句『成功』」這種不可稽核的完成。
2. **還原演練包含「故意毀掉再還原」**:只把備份檔倒回一個空庫,驗證的是
   備份檔的格式;把一個**有資料的庫毀掉再還原到指定時點**,驗證的才是
   「災難那天真正要做的事」。兩者的差距就是演練的價值所在。
3. **MinIO 與 PG 的備份時點要「先物件、後資料庫」**,還原時反過來:
   DB 裡的 `storage_key` 指向物件,若 DB 比物件新,會出現「有 metadata
   沒檔案」的下載 500;反向頂多是「有孤兒物件」,只佔空間不壞功能。
   兩害相權,寧可孤兒不可懸空——這個順序寫死在 runbook,並在演練腳本
   驗證這一點。
4. **cron 段同時掛稽核清理與備份**:兩件事都是「設定值不會自己生效」
   一族(T38 遺留 #1 正式落地),集中在同一節,部署當天照抄即可。
