### 🔴 X-Frame-Options 為什麼要拿掉,不是「兩邊都送 DENY,值一樣沒差」

值相同不代表安全。`X-Frame-Options` 是舊式標頭,語意上**不支援多重值合併**
(不像大多數標頭可以用逗號接起來)。多個瀏覽器對「同一個回應出現兩個
`X-Frame-Options`」的處理方式沒有統一規範——施工單原文說的「行為未定義」
不是保守用詞,是真實風險。維持現狀的話,今天兩邊都是 `DENY` 恰好無害,
但**這條線一旦被日後任何一邊改掉(例如需要同源 iframe 內嵌時只改了 gateway
那一側),App 這邊的殘留標頭會在不知情的情況下製造衝突**。收掉的方式很簡單:
**這個標頭的責任本來就該只有一邊**,拿掉的是 App 這邊,因為 gateway 才是
最終決定「使用者瀏覽器實際收到什麼」的那一層。

`X-Content-Type-Options: nosniff` 施工單沒有點名要拿掉(它是可合併語意的
標準標頭,重複送不構成衝突),所以維持現狀,不過度反應。

### 容器與網路契約:現有 compose 用「network alias」達成同等效果,但補上 `container_name` 求語意精確一致

施工單寫「container_name: upload-program」是**三項硬性約束**之一。
現有 `docker-compose.yml` 沒有設 `container_name`,而是在 `cats-edge`
網路上加了 `aliases: [upload-program]`——這在 Docker 的內嵌 DNS 下**同樣能讓
`upload-program` 這個名字在 `cats-edge` 網路內解析到這個容器**,效果等價。

但施工單的措辭是明確的字面要求,而且下錯的代價是「gateway 解析不到 → 502」
這種現場才會發生、CI 測不到的失效模式。**兩者都設不衝突**,補上
`container_name: upload-program` 讓字面與意圖都對齊,不留模糊空間給下一個
接手的人猜「到底夠不夠」。

### DB 命名:現在改,不是上線後改

`DB_NAME=upload_db`、`DB_USER=upload_user` 與平台規約命名表(`<service>_db` /
`<service>_user`,`service` 取 `upload-program`)不完全一致,少了 `_program`。
**目前無正式資料**(CLAUDE.md 明載),改這兩個值不觸碰任何既有資料列——
純粹是還沒用過的設定值換一個字串。晚改的代價高(要改 `.env`、
`DATABASE_URL`、實際 PG 使用者與資料庫、部署腳本);現在改的代價是
改兩個字串。依施工單 §1 的邏輯(「現在改很便宜,上線後改要動五個地方」)
一併處理。

### 不動的部分:repo 改名

施工單 §6.1 與裁決函 §4 都明確寫「決定權在 Platform,不在 portal」。
本任務**不**擅自把 repo 改名,那是需要與 Platform 團隊另外確認的事——
擅自動了以後 GHCR image 路徑、既有連結全部要跟著改,而且改錯方向的話
是白做。列入待辦,不在本任務動手。

### 為什麼這樣做

**逐項核對,而不是照單全收也不是照單全改。** 施工單九項技術規格裡,
七項現有實作**已經符合**(有的甚至在施工單來之前就因為別的理由做對了——
例如 cookie Path 從設定值直接導出、不依賴請求路徑推導,純粹是 T51 當時
避免「剝前綴造成推導路徑是 `/`」這類錯配的副產品,不是為了這次施工單特地做的)。
真正要改的只有兩項:一個是程式碼缺陷(重複標頭),一個是命名對齊(尚未上線,
改了沒有代價)。這個核對過程本身就是回覆內容的骨幹——回覆文件因此不是照抄
施工單的話術,而是「查完了,結果是這樣」。

**`X-Frame-Options` 拿掉而不是保留「反正值一樣」。** 兩邊都送 `DENY` 在今天
無害,但這個「無害」建立在一個脆弱的假設上:兩邊的值永遠一致。責任本來就
只該有一邊——標頭是「瀏覽器最終收到什麼」的最後一層決定,那是 gateway,
不是 App。這與本專案反覆出現的「同一件事只能有一條路」是同一種判斷,
只是這次「同一件事」的另一份實作在別人的 repo 裡。

**DB 命名現在改。** 尚未上線、無正式資料,這是 CLAUDE.md 明載的事實,
所以改動的代價就是改兩個字串;晚改的代價是要動 `.env`、`DATABASE_URL`、
實際 PG 使用者與資料庫、部署腳本——四個地方,而且極可能是在正式環境改。

**`container_name` 補上而不是說「alias 已經等價,不用改」。** 技術上 alias
確實等價(Docker 內嵌 DNS 兩者都能解析),但施工單的措辭是明確的字面要求,
而失效模式是「gateway 解析不到 → 502,而且健康檢查全綠」——這種現場才會
發生、CI 測不到的錯,寧可字面對齊,不留模糊空間給下一個接手的人猜「到底
夠不夠」。
