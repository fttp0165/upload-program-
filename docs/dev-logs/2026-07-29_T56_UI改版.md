## 計畫(動工前成文,憲法第二條 2)

### 輸入

設計師交付 11 個畫面的互動 mockup(涵蓋全部十個真實畫面 + 未登入首頁的
hero 版本)。設計語言:

- **色盤**:主色藏青 `#1b2a6b`、強調綠 `#2f9e5b`、頁面底 `#eef0f5`、卡片白;
  警示琥珀(未掃描/待開通)、錯誤紅
- **形狀**:膠囊按鈕(`border-radius:999px`)、卡片 12px 圓角 + 頂部 4px 藏青→綠漸層條
- **導航列**:白底 sticky、雙圓 logo(藏青+綠交疊)、品牌名「程式分享平台」、圓角搜尋框
- 麵包屑、圓形分頁鈕、漸層進度條、amber「未掃描」徽章

mockup 本身用 inline style(設計工具格式),**落地時全部轉進 `app.css`**——
設計師自己都在側欄註明了我們的三條限制(禁 inline/外部資源、僅淺色、集中 app.css)。

### 落地策略:CSS 為主、模板微調,**337 條測試一條都不放寬**

行為全部被測試釘住(連結帶前綴、下載在專案資訊之前、not_scanned 可見、
`<details>` 展開數、逸出、文案字串…)。策略:

1. **`app.css` 全面重寫**(設計 token 進 `:root` 變數)——純 CSS 改動幾乎不撞測試
2. 模板只做**加 class / 加包裹層 / 加語意元素**,不刪任何測試釘住的文字與連結
3. 卡片頂部漸層條用 `::before` 偽元素——**零額外標記**
4. 導航列雙圓 logo 用 `.nav-brand` 的偽元素——同上
5. 容量條用原生 `<progress>`(CSP 禁 inline style,動態寬度只有原生元素做得到;
   上傳頁進度條本來就是 `<progress>`,同一套樣式)

### 與設計稿的刻意偏離(記錄在案)

| 設計稿 | 落地 | 理由 |
|---|---|---|
| 「單檔上限 500 MB」 | **100 MB** | 設計稿數字錯誤,以真實設定為準 |
| 拖放上傳區 | 視覺照做,行為仍為選檔按鈕 | 拖放需擴 JS,另列後續;視覺先到位 |
| 待開通頁「複製識別碼」按鈕 | **做**(新增 `static/copy.js`) | T45 曾裁定「為一顆複製鈕不值得開 JS 檔」;設計師把它列為開通流程的第一步,證明它是流程的一部分而非裝飾——推翻先前判斷,理由記此 |
| mockup 的深色側欄(畫面切換器) | 不做 | 那是 mockup 自己的導覽 chrome,不是產品的一部分 |
| 假資料(chen.yuwei、rf-report-builder…) | 不進任何模板 | 僅為展示 |
| 品牌名「程式分享平台」 | 導航列顯示文字採用;`<title>` 仍為 upload-program | 顯示層變更;系統識別不動 |
