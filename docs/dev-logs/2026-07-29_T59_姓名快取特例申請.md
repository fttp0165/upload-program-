## 決策:走契約特例程序,不直接實作

「業務庫只存 `sub`」是契約 §4.2 鐵則,CLAUDE.md 明列本專案**不繼承** PLM 的
姓名快取特例(§6.1)。所以這個需求的正確形狀不是 migration,是**申請書**:

- 產出:[plans/申請_姓名快取特例_給portal.md](../plans/申請_姓名快取特例_給portal.md)(md + HTML,已交 Benny 轉送)
- 申請內容刻意設計成最小揭露/最小權限:僅 `name` claim、來源限本人登入時的
  ID token(**不呼叫 Keycloak Admin API**,零新增權限)、登入時覆寫、
  僅管理後台顯示、不進 log、可整批清除、附契約增修建議稿
- 關鍵論證:維持現狀會催生管理員私記的「誰=哪串 UUID」影子對照表——
  **契約管轄外的個資比受控快取更危險**。這是對 Platform 最有力的理由
- 替代方案評估三案(現狀/Admin API/前端 session)均記錄於申請書 §3
