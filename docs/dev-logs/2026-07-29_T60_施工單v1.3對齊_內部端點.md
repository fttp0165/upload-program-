## 計畫(動工前成文,憲法第二條 2)

### 背景:§4.4 說的事我們踩過,但解法不同

施工單 v1.3 §4.4(sporton_core 實測):容器內連對外網址不通、discovery 的
`jwks_uri` 也是對外網址,故**伺服器端呼叫應走內部位址** `http://keycloak:8080/...`,
`iss` 維持對外(字串比對)。

**我方 2026-07-29 上線當天踩到同一件事**(容器解析 catsapp → keycloak 容器
只聽 8080 → Connection refused),當時的解法是 **hairpin**:
`extra_hosts: catsapp:host-gateway` + 信任內部 CA,讓容器經 host 443 →
portal-gateway 走完整條對外路徑。**能動、線上正在用**,但形態上有代價:

- 伺服器端驗證(token 交換、JWKS)**耦合 gateway**:多繞一跳 TLS + nginx
- 依賴三個部署配件(extra_hosts、host 443 發布、CA 檔路徑)
- 施工單 v1.3 已把「伺服器端走內部」定為平台標準做法(契約 v1.10 §2.4)

### 目標

依施工單 §4.4「建議的設定形態」補上**可覆寫的內部位址設定**(預設空 = 現行
行為不變,向後相容):

| 新設定(.env) | 用途 | VM 目標值 |
|---|---|---|
| `OIDC_DISCOVERY_URL` | discovery 文件的抓取位址(覆寫「從 issuer 推導」) | `http://keycloak:8080/auth/realms/sporton/.well-known/openid-configuration` |
| `OIDC_TOKEN_URL` | code 換 token / refresh(覆寫 discovery 的 `token_endpoint`) | `http://keycloak:8080/auth/realms/sporton/protocol/openid-connect/token` |
| `OIDC_JWKS_URL` | 取公鑰(覆寫 discovery 的 `jwks_uri`) | `http://keycloak:8080/auth/realms/sporton/protocol/openid-connect/certs` |

**不覆寫的東西(紅線):**

- `OIDC_ISSUER` 維持**對外**網址——`iss` 是字串比對,不是連線(§4.4 明文)
- `authorization_endpoint` / `end_session_endpoint` 維持 discovery 的**對外**值
  ——瀏覽器走的必須對外
- discovery 的 issuer 一致性檢查**不放寬**:即使從內部位址抓,文件內的 issuer
  仍是 KC_HOSTNAME 產生的對外值(§4.4 實測),必須等於設定的 `OIDC_ISSUER`
