## 事故二:0006 migration revision 鏈斷裂(v0.1.3 現場爆炸)

`alembic upgrade head` 爆 `KeyError: '0005'`:本 repo 的 revision id 慣例是
**檔名全名**(`0005_audit_events`),0006 卻寫短碼 `0005`。線上 v0.1.3 期間
**登入後頁面 500**(程式查 `display_name_cache`,欄位未建);訪客頁不受影響。
PR #11 修正兩行 id → **v0.1.4 熱修**(遵守「同版不重發」紅線,不覆蓋 v0.1.3)。
**教訓:①寫 migration 先抄前一支的實際 id 慣例;②發版前 `alembic history`
一秒可驗鏈條;③計畫寫了 staging 演練(T59 日誌明載)卻未執行——演練不是儀式,
這次就是它要抓的那種錯。**

## 事故三:runner 與 deploy 互洗 GHCR 憑證

CI 的 publish job 用 `docker/login-action`,其**清理步驟會登出 ghcr.io**;
runner 與 deploy 共用 `/home/deploy/.docker/config.json` → 每次 CI 發版後,
VM 的手動 pull 必 `unauthorized`。當下解法:pull 前重新 `docker login`。
**根治(待辦):runner 服務設獨立 `DOCKER_CONFIG`,讓 CI 登入/登出不碰
deploy 的憑證檔。**
