# T67 側欄「回到平台入口」連結

**建立日期:** 2026-07-31 16:40
**最後更新:** 2026-07-31 17:10
**版本:** v1.1
**對應任務:** T67(新開)——Benny 裁示(附側欄截圖):「增加一個回到入口的連結」

## 計畫(動工前成文,憲法第二條 2)

### 目標

側欄與導航列各加一條**回到平台入口**(catsapp 首頁)的連結。本服務掛在
`/upload/` 之下,使用者從 portal 卡片進來後,沒有回頭路——只能改網址列。

🔴 **這條連結刻意不經過 `url()`**:平台入口是**平台層網址**,加上本服務前綴
會變成 `/upload/` 自己(等於原地打轉)。這與契約 §2.1 的 Account Console
(`/account`)是同一類具名例外,做法一致:
設定化(`PORTAL_HOME_URL`,預設 `/`)→ 由 `templating.render()` 注入 `portal_url`。

### 影響範圍

`app/config.py`(新增 `portal_home_url`)、`app/templating.py`(注入 `portal_url`)、
`app/templates/base.html`(側欄頂端 + 頂列)、`.env.example`、
`tests/test_portal_link.py`(新)、既有 9 個測試檔的 `PLATFORM_URLS` 需納入 `/`。
**對現有資料的影響:🟢 純 UI 與設定,不動資料。**

### ⚠ 這個改動會鬆動一條既有紅線,必須補償

「頁面內所有連結都要帶前綴」的測試以 `PLATFORM_URLS` 白名單放行平台層網址。
把 `/` 加進白名單,等於**未來某個漏掉 `url()` 的首頁連結**(也會長成 `/`)
不再被抓到。補償措施(與白名單同一個 commit):

1. 新增測試斷言頁面上**恰好只有一條** `/` 連結,且它就是平台入口那條;
2. 新增測試斷言品牌連結與側欄「專案總覽」都是 `{PREFIX}/`。

這兩條把原本靠「白名單很小」得到的保護,換成明確的計數與具名斷言。

### 驗收標準

紅→綠:匿名與已開通者頁面都含 `href="/"` 的「回到平台入口」;
側欄該連結在最上方;`portal_url` 可由設定覆寫;
上述兩條補償測試成立;全站既有測試全綠。

### 回滾方式

git revert(單一 commit;純 UI 與設定,無資料異動)。

## 結果(完工後補記)

### 做了什麼(異動檔案)

- `app/config.py`:新增 `portal_home_url`(env `PORTAL_HOME_URL`,預設 `/`),
  註釋寫明它與 `account_console_url` 同屬「平台層網址、不帶本服務前綴」。
- `app/templating.py`:注入 `portal_url`(與 `account_url` 並列)。
- `app/templates/base.html`:側欄最上方一條 `side-exit`「回到平台入口」
  (行內 SVG 箭頭出框圖示)、頂列一條 `nav-exit`(已開通者桌面版 `d-lg-none`,
  避免與側欄重覆——同 T62/T66 的處理)。
- `.env.example`:補 `PORTAL_HOME_URL=/`。
- `tests/test_portal_link.py`(新):6 條,含兩條補償斷言。
- 既有 9 個測試檔的 `PLATFORM_URLS` 納入 `/`(具名例外,附理由與補償指標)。
- `tests/test_web_releases.py`:排序斷言改為只在 `<main>` 內比對(見下)。

### 為什麼這樣做

- **不經過 `url()`**:平台入口加上本服務前綴會變成 `/upload/` 自己,
  等於原地打轉。與契約 §2.1 的 `/account` 是同一類具名例外,做法一致(設定化)。
- **側欄放最上方且獨立一段**:「離開這個 App」與「在 App 裡走動」是不同層級,
  混在同一組連結裡會讓人誤點。
- **白名單鬆動要補償**:把 `/` 加進 `PLATFORM_URLS`,等於未來漏掉 `url()` 的
  首頁連結(也長成 `/`)不再被抓到。補償是把保護換成**具名標記**——
  頁面上每一條 `/` 都必須帶 `nav-exit` / `side-exit`,裸 `/` 會讓測試紅。

### 測試結果(紅→綠)

- 紅:實作前 **5 failed, 1 passed**(缺連結、缺設定、標記計數不符)。
- 綠:`test_portal_link.py` **6 passed**;全套 **377 passed**(新增 6 條),
  `ruff check` 全過。
- 🐛 過程紅燈(值得記):`test_歷史頁依發布時間倒序` 突然紅了——
  原因是本任務新增的行內 SVG 路徑資料含 `v9`(SVG 的垂直線指令 `1v9a1`),
  而該測試用 `body.index("v9")` 在**整頁 HTML** 上找版本號,於是先撞到圖示。
  兩邊都修:圖示改用絕對座標 `V12.5`(不再含版本號樣式的子字串),
  測試改為先切出 `<main>` 再比對——**版面的東西不該影響內容排序的斷言**。

### 對現有資料的實際影響

🟢 純 UI 與設定;無 schema、無資料異動。VM 換版時 `.env` 可不動
(`PORTAL_HOME_URL` 有預設值 `/`);要指向別的入口才需追加該行。

### 遺留問題與後續建議

1. 若 portal 之後把入口改到別的路徑,只需在 VM 的 `.env` 加 `PORTAL_HOME_URL=...`,
   不必改程式。
2. 「頁面上的裸 `/` 連結」這條保護現在依賴 class 標記,新增平台層連結時
   記得沿用 `nav-exit` / `side-exit`(或擴充 test_portal_link.py 的樣式)。
