# T68 首頁顯示版本號 + 憲法納入「發版必附 title 與 content」

**建立日期:** 2026-07-31 17:40
**最後更新:** 2026-07-31 18:00
**版本:** v1.1
**對應任務:** T68(新開)——Benny 裁示:「加入 CLAUDE.md 每次發布 Release 提供 title 跟 content,並且在服務的首頁加入版本號」

---

## 計畫(動工前成文,憲法第二條 2)

### 目標

兩件事,同一個主題(**發版的可辨識性**):

1. **首頁顯示版本號**。目前要確認「線上跑的是哪一版」只能靠挑一個「只有新版才有」
   的靜態檔當哨兵(runbook §A.4),繞了一大圈。版本號印在首頁上,
   使用者回報問題、我方換版驗證都能一眼看到。
   單一真相放在 `app/version.py`;順手修掉 `main.py` 裡寫死的 `version="0.1.0"`
   (已與現實脫節 5 個版本——這正是「同一件事寫兩份」的必然結果)。
2. **憲法納入發版儀式**:每次發 Release **必須提供 title 與 content**,
   不得只推一個裸 tag。content 必含:本版任務、對資料的影響、部署注意事項、測試數。
   同時規定 **`APP_VERSION` 必須在打 tag 前隨 PR 改好**——否則首頁會說謊。

### 影響範圍

`app/version.py`(新)、`app/main.py`、`app/templating.py`、`app/templates/home.html`、
`tests/test_version_display.py`(新)、`CLAUDE.md`(升 v2.2)、
功能需求大綱(F71 補述 / 新增功能項)、任務表。
**對現有資料的影響:🟢 純顯示與文件,不動資料。**

### 驗收標準

紅→綠:首頁(匿名與已登入)顯示 `v{APP_VERSION}`;OpenAPI 的 version 與同一個常數
一致(防再次漂移);版本字串格式受檢;CLAUDE.md 有發版儀式段落與版本歷史;
全站既有測試全綠。

### 回滾方式

git revert(單一 commit;純顯示與文件,無資料異動)。

## 結果(完工後補記)

### 做了什麼(異動檔案)

- `app/version.py`(新):`APP_VERSION = "0.1.6"`,**單一真相**。
  刻意不吃 env 覆寫——版本是「這份程式碼是哪一版」的事實,不是部署參數;
  可覆寫等於允許同一份 image 自稱不同版本。
- `app/main.py`:FastAPI `version=APP_VERSION`(原本寫死 `"0.1.0"`,已脫節五個版本)。
- `app/templating.py`:注入 `app_version`。
- `app/templates/home.html`:頁尾一行 `upload-program v{{ app_version }}`,
  匿名 / 待開通 / 已開通三種狀態都看得到。
- `tests/test_version_display.py`(新):4 條,含**防漂移**斷言(OpenAPI 版本必須等於同一常數)。
- `CLAUDE.md` **v2.2**:新增**第八條〈發版儀式〉**——Release 必附 title 與 content、
  content 四段、`APP_VERSION` 須在打 tag 前改好、同版不重發、發版前 migration 鏈檢查;
  〈位階〉圖同步改為「八條」。

### 為什麼這樣做

- **版本號印在首頁**:原本確認「線上是哪一版」得挑一個「只有新版才有」的靜態檔當哨兵
  (runbook §A.4),每次換版都要重挑,且只有我方看得懂。印在首頁後,
  使用者回報問題報得出版本,換版驗證也變成一眼可判。
- **單一真相**:`main.py` 那個寫死的 `0.1.0` 就是「同一件事寫兩份」的下場——
  沒人會記得改。這次連 OpenAPI 也讀同一個常數,並用測試釘住兩者相等。
- **發版儀式入憲**:Benny 裁示每次 Release 要提供 title 與 content。裸 tag 的問題是
  半年後沒有人(包括我們自己)知道那一版動了什麼;content 四段正好對應
  runbook 換版時真正要問的四個問題(內容、資料影響、部署注意、測試)。

### 測試結果(紅→綠)

- 紅:`app/version.py` 不存在時 **4 failed**(ModuleNotFoundError)。
- 綠:`test_version_display.py` **4 passed**;全套 **381 passed**(新增 4 條),
  `ruff check` 全過。

### 對現有資料的實際影響

🟢 純顯示與文件;無 schema、無資料異動、無 `.env` 變更。

### 遺留問題與後續建議

1. 🔴 **發版流程從此多一步**:打 tag 前先把 `APP_VERSION` 改成該版並隨 PR 合併
   (本次已設為 `0.1.6`)。憲法第八條 4 已明文。
2. runbook §A.4 的「版本哨兵」可改用首頁版本號(比挑靜態檔直觀),
   下次修 runbook 時一併更新。
