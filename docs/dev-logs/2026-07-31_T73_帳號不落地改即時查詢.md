# T73 顯示名稱改為 Admin API 即時查詢(帳號不落地)

**建立日期:** 2026-07-31 21:40
**最後更新:** 2026-07-31 21:40

---

## 計畫(動工前成文,憲法第二條 2)

### 目標

管理後台的使用者顯示名稱改為**向 IdP 即時查詢**,查得的姓名只用於本次頁面渲染,
**不寫入資料庫、不寫入 log**;完成後移除 T59 的 `display_name_cache` 欄位,
並請 portal 撤銷 §6.1 對本服務的具名特例。

### 🔴 前置條件(不能自行跳過)

Admin REST API 需要 **service account + `view-users`**,那是 **portal 才能授予的權限**。
本專案無權自行取得,平台鐵則亦明文「偏離需 Platform 同意」。
申請書已成文:[申請_AdminAPI即時查詢_給portal](../plans/申請_AdminAPI即時查詢_給portal.md)。

⚠️ 這份申請**推翻**我方 2026-07-29 的評估(當時主張 Admin API 授權面過大,
portal 據此核准較小的落地快取)。立場改變已在申請書開頭明講,不遮掩。

**裁示前不動工**——這是 T59 立下、portal 明確要求的慣例。

### 三階段(獲准後才啟動)

| 階段 | 內容 | 資料 |
|---|---|---|
| **A** | `app/idp_directory.py`:client_credentials 取 token(記憶體、含到期)、`GET /users/{sub}` 單筆查、2 秒逾時、失敗回 `None`;請求內去重 | 🟢 |
| **B** | 管理後台(使用者、稽核)改用即時查詢;查不到回退顯示 sub。設定齊全才啟用,未設定時**行為與現在完全相同**(過渡期兩者不並存於畫面) | 🟢 |
| **C** | migration 移除 `display_name_cache`(**🔴 刪欄位=刪資料**:先備份、staging 雙向演練、backward 為重新加回 nullable);`tools/purge_name_cache.py` 一併退場;通知 portal 撤銷具名特例 | 🔴 |

A、B 可一次交付;**C 獨立一個 PR**,因為它是本專案第一個「刪資料」的 migration,
要單獨審、單獨演練、單獨回滾。

### 影響範圍

`app/config.py`(三個新設定,預設空=不啟用)、`app/idp_directory.py`(新)、
`app/routers/web.py`(管理頁)、`app/templates/admin_users.html` / `admin_audit.html`、
`.env.example`、`tests/test_idp_directory.py`(新,以假 IdP 驗行為)、
階段 C 另加 `alembic/versions/0007_drop_display_name_cache.py`。

### 驗收標準

紅→綠:
1. 未設定 Admin API → **行為與現在完全相同**(不呼叫、不報錯)。
2. 設定齊全 → 管理頁顯示 IdP 當下的名字;**assert 資料庫沒有被寫入姓名**
   (這條是本任務的核心,不能只驗畫面)。
3. IdP 逾時/500 → 該列回退顯示 sub,頁面仍 200(不得整頁掛掉)。
4. 同一頁重複 sub **只查一次**(請求內去重)。
5. 姓名**不進 log**:以 caplog 斷言(沿用既有「log 不記個資」的測試模式)。
6. 只用單筆端點,**不呼叫列舉端點**(以假 IdP 記錄被呼叫的路徑來斷言)。
7. 階段 C:migration up→down→up 演練通過,`users` 表確認無姓名欄位。

### 回滾方式

- 階段 A/B:git revert(純新增 + 設定關閉即回舊行為)。
- 階段 C:`alembic downgrade -1` 重新加回 nullable 欄位;**但已刪除的姓名不會回來**
  ——那正是本任務的目的,備份是唯一的還原路徑。
