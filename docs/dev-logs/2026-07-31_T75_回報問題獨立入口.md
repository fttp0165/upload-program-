## 計畫(動工前成文,憲法第二條 2)

### 目標

T66 把「回報網站問題 / 提交功能需求」做成 `/help` 頁**裡面的一個專節**,
沒有自己的入口——從畫面上看等於不存在,Benny 一眼就發現少了。

修法:給那一節一個錨點 `#report`,並在**側欄**與**導航列**各加一條
「回報問題」連結指向 `/help#report`。

**為什麼不做成獨立頁面**:內容只有一段(找誰、附什麼),獨立成頁反而讓
「教學」與「回報」的關係斷開——使用者常常是看完教學才發現要回報。
錨點連結成本最低、資訊不重複,也不會出現兩份會漂移的文案。

### 影響範圍

`app/templates/help.html`(加 `id="report"`)、`app/templates/base.html`
(側欄 + 頂列各一條)、`tests/test_help_page.py`(新增斷言)、任務表。
**對現有資料的影響:🟢 純 UI,不動資料。**

### 驗收標準

紅→綠:回報專節有 `id="report"`;側欄與頂列都有指向 `/help#report` 的連結;
連結一律帶前綴(沿用既有掃描斷言);全站測試全綠。

### 回滾方式

git revert(單一 commit)。
