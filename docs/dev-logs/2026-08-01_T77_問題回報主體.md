## 計畫(動工前成文,憲法第二條 2)

### 目標

可用的站內問題回報:建立、清單、詳情、討論串、狀態機、權限、稽核。
**本期不做附件**(第二期 T78),但形態要能無痛接上。

### 關鍵實作決定(與施工計畫書一致,細節在此定樁)

1. **Markdown 自己寫,不引入套件。**
   `markdown` 套件目前只是 dev 相依(給 `tools/render_docs.py` 用),
   把它變成執行期相依還得再配一個消毒器(bleach 之類)——**兩個新相依,換來一個
   預設允許原始 HTML 的轉譯器**,方向是錯的。
   改寫一支 `app/markdown_lite.py`:**先把整段輸入 HTML 逸出,再只產生我方白名單標籤**。
   白名單不是「事後過濾壞東西」,而是**結構上不可能產生使用者的 HTML**——
   這是本任務最重要的安全決定。
2. **回傳 `Markup` 而非在模板寫 `|safe`。** 憲法禁 `|safe` 是為了防「把使用者輸入當
   HTML 輸出」;本函式的輸出是**我方逐字組出來的**,輸入早已逸出。
   以 `markupsafe.Markup` 回傳,模板照常 `{{ }}`,`|safe` 的禁令維持不變。
3. **不存轉譯結果**,只存 Markdown 原文——轉譯規則改了,全站立即生效。
4. **非本人非管理員一律 404**(不是 403),與 private 專案同一個立場:不洩漏存在。
5. **待開通者可以回報**——他們最可能遇到問題,卻是最沒有管道的人。

### 為什麼這樣做

- **自己寫轉譯器**:`markdown` 套件預設放行原始 HTML,要安全就得再配消毒器
  ——兩個新執行期相依,換來「預設不安全、靠事後過濾補救」。改成
  **先逸出再產生**,使用者的 HTML 在結構上沒有路徑進到輸出。
- **回傳 `Markup` 而非模板寫 `|safe`**:憲法禁 `|safe` 是為了防「把使用者輸入當
  HTML 輸出」;這裡的輸出是我方逐字組的,輸入早已逸出,禁令不必開例外。
- **非本人非管理員回 404 不是 403**:403 等於承認「這件回報存在」。
- **狀態不做「只能照順序前進」**:現實裡問題會來回(修好又壞、關掉又重開),
  硬性流程只會逼人繞路;要守的是「誰能改」與「改了留痕」,那兩件做足了。
- **`app_version` / `page_url` 系統帶入**:使用者不會記得自己看到問題時是哪一版。

### 🐛 過程中修正的兩條「自己寫太嚴」的斷言

1. `javascript:` 連結:原本斷言「字串必須消失」。實際行為是**不產生 `<a>`、
   原文以純文字顯示**——純文字不會執行,真正該釘的是「沒有 `href`」。
2. XSS 端到端:原本在**整頁**斷言 `"<script" not in body`,結果撞到版型自己的
   Bootstrap `<script src=...>`。改為只比對 `<main>` 內容區。

兩次都是斷言寫得比實際紅線更嚴,而不是程式有問題;**修的是測試,不是放寬安全性**
——調整後的斷言仍然涵蓋「不得出現活的標籤」。
