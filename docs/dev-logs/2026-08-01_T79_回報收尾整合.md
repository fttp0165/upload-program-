## 計畫(動工前成文,憲法第二條 2)

### 目標

把回報系統接進既有的維運節奏,並補上保存期。

1. **管理總覽待辦(T70)加一項**:「未處理的回報 n 件」(`open` + `in_progress`),
   點進去到 `/issues`。本平台**沒有 email 也沒有排程器**,這個數字就是管理員唯一的
   提醒機制——沒有它,回報會安靜地躺在資料庫裡。
2. **清除工具** `tools/purge_issues.py`:刪除**已關閉(closed / wontfix)滿 365 天**的
   回報,連同討論串與 MinIO 物件。比照 `purge_audit.py`:**工具 + cron,不自動跑**
   ——刪資料的東西不該在應用程式裡自己啟動。
3. **使用教學補一節**:`/help` 說明回報流程與「不會寄信,請回來看」。

### 影響範圍

`app/dashboard.py`(Todos 加欄位 + 查詢)、`app/templates/admin_dashboard.html`、
`tools/purge_issues.py`(新)、`app/templates/help.html`、
`tests/test_admin_dashboard.py` 與 `tests/test_issues.py`(補測試)。

**對現有資料的影響:🟢 面板與教學頁不動資料;清除工具是 🔴 刪資料,
但它是人工/cron 觸發的獨立腳本,不在請求路徑上。**

### 驗收標準

紅→綠:
1. 有未處理回報時,總覽出現「未處理的回報 n」且**數字正確**;沒有時不出現;
2. 清除工具:**只**刪已關閉滿 365 天者;未達期限、未關閉者一律不動(以 fixture 驗兩側);
3. 教學頁含回報流程與「不寄信」的說明;
4. 全站測試全綠。

### 回滾方式

git revert(面板與教學頁純顯示)。清除工具刪掉的資料**不可回滾**,只能從備份還原
——所以它預設 dry-run,要加 `--yes` 才真的刪。
