## 二、今天真正重要的三件事

### 1. 憲法長出第八條(T68)

起因是 v0.1.6 只推了裸 tag,Release 頁說不出「這一版是什麼」。裁示後入憲:
**每次發布必附 title + content 四段**(本版內容 / 資料影響 / 部署注意 / 測試),
且 🔴 `APP_VERSION` 必須在**打 tag 之前**隨 PR 改好——版本號顯示在首頁,
tag 與常數不一致等於對使用者說謊。今天已照此把 `APP_VERSION` 推到 **0.2.0**。

同一天也吃到第八條 5(同版不重發)的實例:v0.1.6 的 tag 指在 T68 的 merge 上,
T69 更名沒搭上車,**不改 tag、改發下一版**,直接開 PR 把 `APP_VERSION` 推到 0.1.7。

### 2. SSO 契約升到 v2.0,同時給了義務也抽掉了路(T74 / T73)

- **給了義務**:v2.0 新增 §10 單一登出。我方 session 是 HttpOnly cookie 形態,
  **沒有豁免空間**,當天就把 front-channel logout 端點做出來(T74)。
  端點刻意**不宣告 `iss` / `sid`**,理由寫在任務日誌裡。
- **抽掉了路**:v2.0 §4.2a L1 顯示名稱快取通則**明文禁止呼叫 Admin API**。
  Benny 早上裁示的「改 Admin API 即時查詢、只顯示不落地」(T73)因此**不再是
  申請一個 `view-users` 權限就能解**——它現在要求改的是平台通則。
  🔴 **T73 維持不動工**,申請書需要重寫成「請求變更 §4.2a L1」而非「請求授權」。

### 3. 問題回報系統,以及本專案第一條 inline 下載路徑(T77–T79)

Benny 要的是「富文本、可貼照片、有清單、管理員可回覆、記錄進度與關閉狀態」。
先出設計文件與施工計畫書(五題建議裁示),得到「照建議做」後才動工,分三期落地。

技術上兩個要記住的地方:

- **`app/markdown_lite.py` 是逸出優先再白名單**,不是 sanitizer。
  先 `escape()` 整段,再只把白名單樣式轉回標籤;外部圖片一律剝除,
  `javascript:` / `data:` 永遠不會變成 `href` / `src`——它們留在頁面上是**無害純文字**。
  `tests/test_markdown_lite.py` 是這條路徑唯一的安全網,**不得刪改**。
- 🔴 **`GET /v1/issues/{id}/attachments/{aid}` 是本專案第一條 `Content-Disposition: inline`**。
  截圖要看得到就得 inline,代價用六條收窄:僅三種點陣圖型別 / 上傳驗 magic bytes +
  回應前再驗一次 / 仍送 nosniff / 5 MB × 5 個上限 / 僅本人與管理員(不存在回 404)/
  舊的 `/v1/releases/.../download` 由**回歸測試**釘住 attachment 不受影響。
