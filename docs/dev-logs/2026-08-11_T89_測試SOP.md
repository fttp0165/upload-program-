## 計畫(動工前成文,憲法第二條 2)

### 起因

Benny 指示:「你現在是一個軟體測試工程師,請依照專業針對這個專案寫一份測試 SOP」。

現況:測試紀律**存在但散落**——第三條寫了 TDD 原則,conftest 寫了替身的設計理由,
43 個測試檔的檔頭各自記著紅線,dev-log 裡躺著假綠、只改一半、載體選擇這些教訓。
**沒有一份文件把「在這個專案怎麼做測試」從頭到尾講一遍**;新人要拼湊十幾份文件
才知道規矩,而拼不齊的部分就會重演已經踩過的坑。

### 目標

一份「照著做」的測試 SOP(比照 runbook 的定位),涵蓋:
環境準備、日常執行、TDD 流程、撰寫規範、安全測試對照表、
migration 演練、CI 判定、換版驗證,以及**本專案實際踩過的陷阱**。

### 原則

1. **每一條規則都要能指回真實事件或任務編號**——本專案的文件風格是
   「這條紅線是誰用什麼代價換來的」,不寫教科書式的泛論。
2. SOP 屬第四條 4 明列的正式文件:**md + HTML 並存**,入 `render_docs.py` 產生清單。
3. 不發明新規矩。SOP 是把既有紀律**收攏**,與憲法/runbook 衝突時以它們為準並回頭修正 SOP。

### 影響範圍

`docs/測試SOP.md`(新)、`tools/render_docs.py`(TARGETS 加一行)、任務表。

**對現有資料的影響:🟢 不動資料**(純文件)。

### 為什麼沒有新測試

純文件(第三條 4);`render_docs --check` 守 md/HTML 同步,既有 506 條維持全綠。

### 驗收標準

1. SOP 含:環境、執行、TDD 流程、撰寫規範、安全對照表、migration、CI、換版驗證、陷阱;
2. 每條可考據的規則都附任務編號或事件出處;
3. md + HTML 同步(`--check` 無差異);
4. 全站測試維持全綠。

### 回滾方式

純文件:git revert 即可。

## 結果

### 做了什麼

| 檔案 | 異動 |
|---|---|
| `docs/測試SOP.md` + `.html` | 新增(11 節 + 版本歷史;HTML 由 render_docs 產生) |
| `tools/render_docs.py` | TARGETS 加一行 |
| `docs/任務表.md` | T89 列 + v1.66 |

### 收攏了什麼

- **策略形狀**:為什麼主體是整合式測試(風險集中在路由×權限×逸出×標頭的組合,
  切太細會漏組合錯誤——T59 兩個迴圈各看都對就是例子)。
- **撰寫規範五條硬規則**,全部有出處:真實路徑寫入(T84)、前提斷言(T84)、
  區塊斷言(T85/T59)、invariant 不字面(T85)、成對逸出斷言(T77/T84)。
- **紅線↔守護測試對照表 13 列**:改動觸及紅線時先看右欄檔頭再動手。
- **十條實踩陷阱**:全部指回真實任務,無教科書泛論。

### 驗證

- `render_docs --check` 無差異(md/HTML 同步);
- 全套 **506 passed**、`ruff check` 乾淨(純文件,數字不變是預期)。

### 對現有資料的實際影響

🟢 **無**。

### 遺留問題與後續建議

1. **SOP 是快照,教訓還會再長。** §11 已寫維護規則:新坑 → §10 加列 + 升版;
   憲法/runbook 修訂 → 回寫本文。它會不會爛掉,取決於這條有沒有被執行。
2. 對照表列的是「檔案」不是「測試名」——測試改名不會壞表,但檔案改名會;
   日後若拆檔,記得回來改表。
