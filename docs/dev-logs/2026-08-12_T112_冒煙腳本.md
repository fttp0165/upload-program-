## 計畫(動工前成文,憲法第二條 2)

### 起因

Benny:「可以寫測試腳本驗證嗎?如果不行寫測試 SOP」。

答案是**部分可以**,而且該把界線畫清楚:

| 層 | 現況 |
|---|---|
| 清單標 ✅ 的 97 項中多數 | **早已有腳本**——506 條 pytest,CI 每次跑 |
| 冒煙裡「對著正式站打 curl」的部分 | 目前是 runbook §A.4 的**人工貼指令**——**可腳本化,本任務做** |
| 真實 IdP 登入畫面、貼上/拖放、跨 App 登出、視覺 | 腳本構不到,維持 🖐 人工(清單/SOP 已管) |

### 目標

`tools/smoke.sh`:一鍵執行換版冒煙中可腳本化的檢查,逐項印 ✅/❌/⏭ 並以
exit code 回報,對應清單編號(J-01/J-02/K-06/A-01/A-12/I-01/I-02)。

### 🔴 界線:不為了自動化而破紅線

登入後的項目(下載標頭、管理頁、上傳三格)**不硬塞帳密自動化**:
契約只允許 Authorization Code + PKCE,ROPC(密碼直換 token)是禁手;
把測試帳密放進腳本或 VM 環境變數,違反「secret 不進 git」的精神且多一份外洩面。
這些項目腳本印 ⏭ SKIP 並指回清單,由人工執行。

### 設計

- 參數:`--base URL`(預設正式站)、`--expect vX.Y.Z`(哨兵判定)、
  `--local`(本機模式:無 gateway、X-Frame-Options 預期 0)、`--vm`(加 `/ready` 容器內檢查)。
- 檢查:對外路徑 200、靜態檔 200、**版本哨兵**(`/help` 頁尾)、匿名瀏覽器 302 → 登入、
  nosniff / CSP / X-Frame-Options 恰一個、既有系統零影響、`/ready`。
- 部署方式比照 `backup.sh`:**隨 compose 一起 scp**(正式機不 git pull)。

### 腳本自身怎麼測(第三條)

1. **pytest 守門(先紅後綠)**:`tests/test_smoke_script.py`——腳本存在、`bash -n`
   語法通過、關鍵檢查字串齊備。寫在腳本之前,先紅。
2. **本機實跑**:以測試設定起真的 uvicorn,`smoke.sh --local --expect v0.2.1` 全過;
   再以 `--expect v9.9.9` **負向驗證**——判定會咬人才算數(哨兵教訓)。

### 影響範圍

`tools/smoke.sh`(新)、`tests/test_smoke_script.py`(新)、runbook §A.4(升 v1.8)、
測試項目清單(升 v1.1)、任務表。

**對現有資料的影響:🟢 不動資料**(唯讀 curl;不碰 DB、不碰物件儲存)。

### 驗收標準

1. pytest 守門紅→綠;
2. 本機 `--local --expect v0.2.1` 全 ✅、exit 0;`--expect v9.9.9` 有 ❌、exit 非 0;
3. 登入後項目印 ⏭ 並指回清單,不假裝驗過;
4. 全站測試全綠。

### 回滾方式

純新增工具與文件:git revert 即可。

## 結果

### 做了什麼

| 檔案 | 異動 |
|---|---|
| `tools/smoke.sh` | 新增(一鍵冒煙;--base/--expect/--local/--vm) |
| `tests/test_smoke_script.py` | 新增守門 2 條(`bash -n` + 關鍵檢查字串) |
| `docs/runbook_換版與備份還原.md` | v1.8:§A.4 加一鍵入口,逐條指令保留作後備 |
| `docs/測試項目清單.md` | v1.1:標注腳本化範圍;A-01 改 ✅+🖐 |

### 紅 → 綠(兩層)

1. **pytest 守門**:先寫,`2 failed`(檔案不存在)→ 寫腳本 → `2 passed`。
2. **本機實跑**:以測試設定起真 uvicorn,
   - 正向 `--local --expect v0.2.1`:**7 ✅ / 0 ❌ / 4 ⏭,exit 0**;
   - 負向 `--expect v9.9.9`:**1 ❌,exit 1**——判定會咬人。
   - ⚠️ 第一次量負向 exit 時接了 `| tail`,量到的是 tail 的 0——重量才是 1。
     管線會吃掉 exit code,驗 exit 不得接管線。

### 🐛 實跑抓到的腳本 bug(這正是「腳本也要被測」的理由)

哨兵原本裸抓頁面第一個 `vX.Y.Z`,結果撿到 **/help 教學內文裡的範例版本號 v1.0.0**
而不是頁尾。改錨定 T68 的固定格式 **`upload-program vX.Y.Z`**——那才是哨兵。
沒有本機實跑,這個 bug 會一路睡到換版當天,然後在正式機上「誤報換版失敗」。

另收一次 T12 同款:scratchpad 的 runner 以路徑執行時,腳本目錄不在 `sys.path`,
`No module named 'app'`——同一課第二次上。

### 界線(為什麼不「全部」自動化)

登入後項目不硬塞帳密:契約只允許 code + PKCE,ROPC 是禁手;帳密進腳本或 VM
env 就是多一份外洩面。腳本對這些印 ⏭ SKIP 指回清單——**跳過要看得見**。

### 對現有資料的實際影響

🟢 **無**(唯讀 curl)。

### 遺留問題與後續建議

1. **腳本要隨 compose scp 到 VM** 才用得上(比照 backup.sh)——下次換版時帶上。
2. 日後若做 staging 且可安全放測試帳號,可再評估以 Playwright 走真登入,
   把 E-02/G-01 也腳本化;現階段不做。
