## 計畫(動工前成文,憲法第二條 2)

### 起因

T115 修好「中文文字檔被判成 binary」,但**修正要換版才生效**——正式站仍跑 v0.2.1,
Benny 那份 `客戶規格書.md` 在換版前依舊傳不上去。Benny 裁示發下一版。

憲法第八條 4:`APP_VERSION` 必須在打 tag **之前**隨 PR 改好。本任務就是那一步。

### 這一版帶什麼(v0.2.1 之後未合併的 6 個任務)

| 任務 | 影響執行中的服務? |
|---|---|
| T115 中文文字檔判型修正 | ✅ **是**——本版的主角 |
| T113 session cookie 無法解析時記 warning | ✅ 是(純觀測,行為不變) |
| T114 憲法第九條 + 文件規約守門測試 | ❌ 否(文件與測試) |
| T112 `tools/smoke.sh` 一鍵冒煙 | ❌ 否(工具,隨 compose scp) |
| T111 測試項目清單 / T110 測試 SOP | ❌ 否(文件) |

### 為什麼是 0.2.2 而不是 0.3.0

沒有新功能面:一個 bug 修正、一個觀測補強,其餘是文件與測試。
patch 語意上正確的位置是 **0.2.2**。

### 為什麼不重發 v0.2.1

第八條 5:同一個版本 tag 不重發(v0.1.3 事故的結論)。v0.2.1 已發布且**已部署到 VM**,
移動 tag 會讓「使用者手上那一版」與「tag 說的那一版」變成兩件事。

### 影響範圍

`app/version.py` 一行。文件:任務表、本日誌。**對現有資料的影響:🟢 不動資料。**

### 為什麼不寫新測試(憲法第三條 4)

版本號的既有測試(`test_version_display.py`、`test_issues.py`、`test_admin_dashboard.py`)
全部**讀同一個常數**再比對畫面,改常數後它們自動驗新值——這正是 T68 把單一真相
收在 `app/version.py` 的用意。再寫一條 `assert APP_VERSION == "0.2.2"` 只是把同一個
字面值抄第二遍,抓不到任何錯誤,只會製造「改版本要改兩個地方」的摩擦。
比照第三條 4:不寫新測試,既有測試維持全綠當安全網。

### 驗收標準

1. `APP_VERSION == "0.2.2"`;
2. 全站測試全綠;`ruff check` 乾淨;
3. CI 三 job 綠燈。

### 回滾方式

純常數、無 migration:改回字串即可。
