## 計畫(動工前成文,憲法第二條 2)

### 起因

Benny:「部屬 本地 WSL 跑 CI」——要能在自己的 WSL 上把服務跑起來,
並且在推之前先在本機跑過 CI 的那四關。

### 現況盤點:README 現在給的指示是**錯的**

README §本地開發 最後一句:

> 啟動服務需要 PostgreSQL 與 MinIO,最省事的方式是 `docker compose up -d`。

在 WSL 上照做**必然失敗**,三個原因:

| 障礙 | 為什麼 |
|---|---|
| `networks: cats-edge: external: true` | 那是 Cats VM 上 gateway 的網路,本機沒有,compose 直接報錯 |
| `image: ghcr.io/fttp0165/upload-program:v0.1.3` | 要 `docker login ghcr.io`,而且拉到的是**舊版 image**,不是你本機的程式碼 |
| `volumes: /home/deploy/cats-ca/catsRootCA.crt` | VM 上的內部 CA 憑證路徑,本機沒有這個檔 |

`docker-compose.yml` 是**正式機形狀**,本來就不該拿來當本機開發環境。
依第二條 5,這句錯誤指示要回寫,不能留著。

### 好消息:CI 的主力關卡本機完全跑得動

`tests/conftest.py` 用 **SQLite in-memory + 假 S3 端點**,
所以 523 條測試**不需要 PostgreSQL、不需要 MinIO、不需要網路**。
lint 與文件同步檢查同理。也就是說:

| CI job | 本機可跑? |
|---|---|
| 測試 / lint / 文件同步 | ✅ 完全可跑,只要 venv |
| Build image + Trivy | ✅ 可跑,需要 Docker |
| Push GHCR | ❌ 不跑(只在版本 tag,而且不該從本機推) |

**真正需要 DB / MinIO 的只有「用瀏覽器實際操作」這件事。**

### 目標

1. **`docker-compose.dev.yml`(新)**:只起 PostgreSQL + MinIO,發布到 localhost,
   程式本身用 venv 的 uvicorn 跑(改一行就看得到,不必重建 image)。
2. **`docs/runbook_本地開發與CI.md`(新,md + HTML)**:從零到跑起來的逐條指令,
   加「本機跑 CI 四關」與「常見卡關」。
3. **README 回寫**那句錯誤指示。

### 🔴 最大的風險:dev compose 被誤用到正式機

正式機紅線白紙黑字:**DB / MinIO 不對主機發布 port**、不上 `cats-edge`、
production compose 不用 `latest`。而 dev compose 為了本機能連,**一定要發布 port**——
這兩件事互相矛盾,所以它絕不能有機會被貼到 VM 上跑。

防線三層:

1. **檔名分開**:`docker-compose.dev.yml`,不是 override(`docker-compose.override.yml`
   會被 `docker compose up` **自動吃進去**,那才危險)。要用得明寫 `-f`。
2. **檔頭大字警告** + 刻意**不寫** `restart: unless-stopped`
   (正式機的服務要自動重啟,本機不要——這個差異本身就是一道標記)。
3. **測試守門**:`tests/test_dev_compose.py` 斷言 dev compose **不得**出現
   `cats-edge`、`ghcr.io`、`restart:`;正式 compose **仍須**保有 `cats-edge`
   與「不發布 port」。**兩邊一起釘**,才不會有人把 dev 的形狀改到正式檔去。

### 🔴 本機**不會有**的東西(要誠實寫進 runbook)

**登入不能用。** OIDC 是真的 Keycloak,而 `http://localhost:8000/...` 這個
redirect URI **沒有登記在 client 上**(契約 §4:redirect URI 逐字比對)。
本機能看的是匿名頁(`/help`、`/health`),登入後的行為請靠 523 條測試。

不會為了本機方便去要求 portal 加一個 localhost redirect URI——
那等於在正式 client 上開一個指向開發者機器的洞,不成比例。

### 影響範圍

`docker-compose.dev.yml`(新)、`docs/runbook_本地開發與CI.md`(新)、
`tests/test_dev_compose.py`(新)、`README.md`(回寫)、
`tools/render_docs.py`(TARGETS)、任務表、本日誌。

**對現有資料的影響:🟢 不動資料**(新增本機用檔案,不碰正式 compose 的任何一行)。

### 驗收標準(紅→綠)

1. 守門測試先紅(檔案不存在)→ 補上後綠;
2. 守門測試涵蓋「dev 不得有 cats-edge / ghcr.io / restart」與
   「正式 compose 仍有 cats-edge 且 db/minio 不發布 port」;
3. README 那句錯誤指示已回寫;
4. 全站測試全綠、`render_docs.py --check` 同步。

### 回滾方式

純新增檔案與文件:`git revert` 即可。正式 compose 未動,不影響任何部署。

### 紅 → 綠

5 條先寫:`3 failed / 2 passed`——**正式機那兩條護欄本來就該綠**
(它們守的是「正式檔沒被改成 dev 的形狀」,與 dev 檔存不存在無關)。
補上 dev compose 後 5 條全綠;全站 **528 passed**、ruff 乾淨、
`render_docs.py --check` 同步。

### 不只用眼睛看 YAML

`docker compose -f docker-compose.dev.yml config` **實際執行通過**——
compose 自己的解析器認可,不是我讀過覺得沒問題。
(第三條 5:測試全綠指實際跑過。YAML 縮排錯了肉眼常常看不出來。)

### 查證後修掉的兩個「本來會寫錯」

1. **`PUBLIC_BASE_URL` 不必改**。原本打算叫 Benny 改成 localhost,查
   `web_urls.web_url()` 後發現頁面連結一律是 **root-relative**
   (刻意的:TLS 在 gateway 終結,絕對網址會推導出 `http://`)——
   絕對網址只用在 OIDC redirect,而那本來就不通。少改一行就少一個出錯點。
2. **啟動 log 會有 `error`,而且是正常的**。`main.py` 的 lifespan 對
   discovery 失敗**刻意不擋啟動**。不先講,Benny 一定會以為裝壞了。
   連帶把 `/health` ✅ 與 `/ready` ❌ 的本機預期寫成表——
   否則他會拿 `/ready` 判活著,然後得到錯的結論。

### 對現有資料的實際影響

🟢 **無**。正式 `docker-compose.yml` **一行未動**,不影響任何部署。

### 遺留問題與後續建議

1. **本機登入不能用**且刻意不解決(§5)。要點登入後的畫面只能上正式站;
   登入後的行為由 528 條測試涵蓋。
2. dev compose 用的是**假密碼明碼寫在檔案裡**——這是刻意的(本機用),
   但因此它**永遠不能**變成正式檔。三層防線都在,測試也釘住了。
3. 若日後真要本機驗登入,正解是**自架一個本機 Keycloak**(dev compose 加一個
   service + 自己的 realm),而不是去要求 portal 在正式 client 上加
   localhost redirect URI。目前不做。
