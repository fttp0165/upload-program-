## 計畫(動工前成文,憲法第二條 2)

### 起因

Benny 對 T89 的回饋:「我想要你做的是依照這份專案**量身訂做**一份軟體測試工程師
**會測試的項目**」——T89 的 SOP 是流程(怎麼測),他要的是**清單(測什麼)**:
一個測試工程師拿著就能逐項執行的東西。

### 目標

`docs/測試項目清單.md`:依使用者旅程(登入→開通→專案→版本→上傳→下載→回報)
加四個跨切面(管理後台、安全、維運、介面)逐項列出測試項目,每項含
**條件 → 動作 → 預期**、執行方式(✅ 自動 / 🖐 人工)、是否屬換版冒煙(✓)。

### 原則

1. **從實作長出來,不從模板抄。** 每一項對得上真實功能(F 編號/T 編號的產物);
   模板式的「輸入框長度測試」這類與本系統無關的不列。
2. **標明自動化分工。** 506 條自動測試已覆蓋的項目標 ✅(CI 每次跑,人工只抽查);
   **🖐 人工項才是測試工程師的主力**——真實 Keycloak、貼上/拖放/取消這類瀏覽器
   行為、跨 App 登出、視覺與版面、VM 上的 cron 與備份,自動化構不到。
3. 三種使用情境:**換版冒煙**(只跑 ✓ 項)、**全回歸**(大版本前跑全表)、
   **新功能驗收**(跑該區 + 安全跨切面)。
4. 正式文件:md + HTML、入 render_docs、附一張測試地圖 SVG(第四條 5–6)。

### 影響範圍

`docs/測試項目清單.md`(新)、`docs/assets/test-map.svg`(新)、
`tools/render_docs.py`(TARGETS 加一行)、`docs/測試SOP.md`(補互指連結,升 v2.1)、任務表。

**對現有資料的影響:🟢 不動資料**(純文件)。

### 驗收標準

1. 覆蓋 11 個區域、約百項,逐項「條件→動作→預期」一行可執行;
2. 每項標 ✅/🖐 與冒煙 ✓;冒煙子集可在 15–20 分鐘內人工跑完;
3. md + HTML 同步;全套測試維持全綠。

### 回滾方式

純文件:git revert 即可。
