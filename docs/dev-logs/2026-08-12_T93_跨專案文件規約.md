## 計畫(動工前成文,憲法第二條 2)

### 起因

Benny:「寫入 claude.md 給文件 標明專案 日期與時間,要提供其他專案串接檔名標明
給予傳案與授予專案 日期與時間」。

翻成規約語言,是兩件事:

1. **每份文件都要說得出自己屬於哪個專案**——第七條只管了日期/版本,沒管專案。
   文件一旦離開 repo(附件、列印、貼進聊天),抬頭沒有專案名就認不出來源。
2. **要交給其他專案的文件,檔名本身就要說明「誰發給誰、什麼時候」**——
   不能只靠內文,因為對方收到的往往只有一個檔名。

### 現況盤點(動工前已完成)

`docs/plans/` 13 份,其中 **9 份是跨專案文件**(對 cats-portal),4 份是內部設計。
問題全在眼前:

| 症狀 | 例子 |
|---|---|
| 收發欄位**四種寫法** | `發文方/收文方`、`受文方/發文方`、`申請方`、`From/To`(英文) |
| 3 份**完全沒有**收發欄位 | `SSO接入申請_給portal`、`回覆_portal施工單`、`待portal提供資訊` |
| 檔名只看得出**對象**,看不出來源與時間 | `申請_姓名快取特例_給portal.md` |
| 唯一帶日期的檔名格式又不同 | `狀況同步_給portal_20260729上線.md` |

對方(portal)回給我們的檔名同樣是災難——上一封收到的是
`catsportal____uploadprogram_____.md`,中文全被吃掉,只剩底線。
**規約要能救的正是這種情況。**

### 目標

1. **憲法新增第九條**〈文件識別與跨專案文件規約〉。
2. **可執行**:新增 `tests/test_doc_conventions.py` 自動守門——規約若只寫在憲法裡而
   沒有測試,三個月後就是一句沒人記得的話。
3. **既有 9 份補標**:抬頭統一為 `專案 / 發文專案 / 受文專案 / 發文時間`。
4. **索引**:`docs/plans/跨專案文件索引.md` 一頁看完「發過什麼、給誰、何時、還在等什麼」。

### 🔴 界線:既有檔案**不改名**

9 份舊檔被 dev-logs、任務表、render_docs.py 引用共 **40+ 處**,其中多數在開發日誌裡。
開發日誌是**當時發生了什麼的紀錄**,為了套用今天才訂的規則去回頭改寫,
是拿新規則竄改舊歷史——第六條的精神反對這件事。

所以:**規約對「本條生效後新建的文件」有強制力**;既有檔案維持原名,
以索引補齊 metadata。新舊之間的橋是索引,不是大規模改名。
(唯一例外見下:今天才建、只有 4 處引用的 T92 回覆文件,趁未送出先更名示範。)

### 命名格式

```
<發文專案>_致_<受文專案>_<類別>_<主題>_<YYYYMMDD-HHmm>.md
```

- 類別限六種:`申請` / `通報` / `回覆` / `聲明` / `同步` / `交付`
- 時間是**發文時間**(第一次送出),不隨改版變動——對方靠它對帳
- 收到的他方文件放 `docs/plans/inbox/`,同格式(來源在前,故自然分群)

### 影響範圍

`CLAUDE.md`(新增第九條,升 v2.4)、`docs/plans/*.md` 9 份抬頭、
`docs/plans/跨專案文件索引.md`(新)、`tests/test_doc_conventions.py`(新)、
`tools/render_docs.py`(TARGETS 路徑)、任務表。

**對現有資料的影響:🟢 不動資料**(純文件與測試,不碰 DB / 物件儲存 / 執行路徑)。

### 驗收標準(紅→綠)

1. 守門測試先紅:既有跨專案文件缺少統一抬頭欄位 → 失敗;
2. 補標後轉綠;
3. 新格式檔名可被解析(發文專案/受文專案/時間三段皆取得出);
4. 索引所列檔案**都存在**(防止索引與現實漂移);
5. 全站測試全綠、`render_docs.py --check` 乾淨。

### 回滾方式

純文件與測試,無 migration、無執行路徑異動:`git revert` 即可。
