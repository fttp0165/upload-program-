## 計畫(動工前寫,第二條 2)

### 目標

「建立新版本」表單要看得到**這個專案已經有哪些版本號**。

Benny 實測回報(附截圖):版本號欄位只有 placeholder `v1.0.0` 與「不強制 SemVer」,
**要填的人手上沒有前一版是什麼**。

🔴 這不只是方便:版本號有 UNIQUE 約束,撞號的下場是送出後才看到
「欄位不正確 / 已存在」——而且要離開這一頁去查歷史才知道該填什麼。
版本號的正確值是「上一版的下一個」,那個資訊本來就該在輸入框旁邊。

### 做法

- `GET/POST /projects/{slug}/releases/new` 兩條路徑都查 `queries.query_releases()`
  (**與 API、版本歷史頁同一份查詢**,不另寫排序),取最新 5 筆 + 總數。
- `include_drafts=True`:能進到這一頁的人至少是 maintainer,草稿是他自己的工作區;
  🔴 **草稿必須標示出來**——不標的話,看到 `v1.1.0` 已存在卻找不到它發布在哪。
- 模板在版本號欄位下方列出版本號 + 總數 + 連到版本歷史。
- 一個版本都沒有時寫「這是第一個版本」,不留空白區塊。

### 影響範圍

- `app/routers/web.py`(`new_release_form` / `create_release_form` 的 `_back`)
- `app/templates/release_new.html`
- `app/static/app.css`(版本號清單樣式)
- `tests/test_release_history_hint.py`(新增)

**對現有資料的影響:🟢 不動**(唯讀查詢,無 migration、無欄位、無 UPDATE)。

### 驗收標準

1. 已有版本時,建立版本頁列出版本號(最新在前)與總數。
2. 草稿版本標示「草稿」。
3. 沒有版本時顯示「這是第一個版本」。
4. **送出失敗重新渲染表單時,清單仍在**(填錯的那一次最需要它)。
5. 🔴 只列**本專案**的版本——別的專案的版本號不得出現(權限與存在性不得外洩)。
6. 全套測試綠燈。

### 回滾方式

`git revert` 單一 commit;唯讀查詢,無資料痕跡。

### 測試(紅 → 綠)

```
# 紅(實作前)
FAILED test_建立版本頁列出已有的版本號
FAILED test_草稿版本標示為草稿
FAILED test_還沒有版本時說這是第一個版本
FAILED test_送出失敗重新渲染時清單仍在
4 failed, 1 passed

# 綠(實作後)
5 passed        # test_release_history_hint.py
513 passed      # 全套(508 → 513)
```

⚠ **第一版測試有兩條是假綠**:整頁搜尋 `v1.0.0` 會撞到版本號欄位的 **placeholder**
——什麼都不做也會通過。改成只在 `.version-hint` 區塊內比對,並把測試資料換成
`v2.3.4` / `v5.0.0` 等不會與 placeholder 相同的值。**那種綠燈比紅燈危險。**

### 🐛 施工中抓到的真缺陷(第二條 5 回寫)

計畫寫「GET 與 POST 兩條路徑都查」,實作後 `test_版本號重複時回到表單並顯示訊息`
(既有測試)當場紅:

```
sqlalchemy.exc.MissingGreenlet: greenlet_spawn has not been called
```

**根因:** 撞號那條路徑會先 `await session.rollback()`,rollback 讓先前查出來的
`Release` 物件全部過期,模板讀 `release.version` 就變成非同步環境外的 IO。
這是本 repo **第四次**同型事故(T44 兩次、T77 一次)。

**修法:** 把清單查詢搬進 `_back()` 內部(rollback 之後才查),`_back()` 改為 async。
**沒有**選擇「失敗頁就不顯示清單」——填錯的那一次最需要看到已有哪些版本號。

⚠ 順手踩到的坑:同一個檔案裡有兩個 `_back()`(建立專案、建立版本),
字串替換把建立專案那個也改成 `await`,由 `test_表單回填的值有逸出` 抓到。

### 對現有資料的實際影響

🟢 **不動。** 唯讀查詢(每頁最多 5 筆 + 一次 count),無 migration、無 UPDATE。

### 遺留問題與後續建議

1. 沒有做「自動填入下一個版本號」——那要猜版號規則(平台明文不強制 SemVer),
   猜錯會讓人以為系統認定了某種格式。**顯示事實、不代替決定。**
2. 清單固定 5 筆(`_VERSION_HINT_LIMIT`);超過時給「看完整版本歷史」連結。
