## 計畫(動工前寫,第二條 2)

### 目標

讓 T89 / T90 / T91 的介面改動**能在本機(WSL)用瀏覽器看到**,一條指令、
不需要 PostgreSQL、MinIO、也不需要 Keycloak。

### 為什麼需要它(問題本身)

Benny 要在本機 WSL 驗證,而**現況做不到**:

| 要看的東西 | 現況為什麼看不到 |
|---|---|
| T89 側欄入口連結 | 側欄只在**已開通登入者**的版型出現 → 需要 Keycloak |
| T90 建立版本頁的版本清單 | 需要登入 + 專案 + 版本資料 → 需要 Keycloak + PG |
| T91 教學頁三張圖 | `/help` 匿名可看,但服務起不來就什麼都看不到 |

`docker compose up -d` 只給 PG + MinIO,**沒有 IdP**;而本專案的紅線是
「不自建帳號系統」,所以本機不可能靠自己登入。結果是介面改動只能靠讀 HTML
或等部署到 VM——**而 T85、T86 的教訓都是「等實測回報」太慢**。

### 做法

`tools/devserver.py`:用**測試已經在用的替身**(`tests/conftest.py` 的 `FakeOidc`、
`FakeStorage`)把真的 app 跑起來:

1. SQLite 檔(`.devdata/dev.db`)取代 PG;`FakeStorage` 取代 MinIO。
2. 造一個**已開通的管理員**假帳號 + 一個示範專案 + 兩個版本(一個 draft
   ——T90 的草稿標示要看得到)。
3. 多一條 `GET /dev/login`:直接種 session cookie(用 `FakeOidc` 發的假 token),
   等同「已登入」。**這條路由只掛在 devserver 建的 app 上**,不在 `create_app()`。
4. 只綁 `127.0.0.1`。

### 🔴 這支腳本會偽造 session,所以安全性靠三層結構,不靠自律

1. **沒有 `DEV_UNSAFE_LOCAL=1` 就拒絕啟動**(不是警告,是 `SystemExit`)。
2. **只綁 `127.0.0.1`**,原始碼裡不得出現 `0.0.0.0`。
3. 🔴 **image 裡根本沒有這支腳本**:`Dockerfile` 只 `COPY app/`、`alembic/`,
   而 devserver 依賴 `tests/`——**兩層都不在 image 內**,正式環境連 import 都會失敗。
   這是結構保證,不是設定選項。

以上三條 + 「`app/` 任何檔案都不得 import 它」都寫成測試反向驗證。

### 影響範圍

- `tools/devserver.py`(新增)
- `tests/test_devserver.py`(新增)
- `README.md`(本地開發段補一段用法;依第七條升版)
- `.gitignore`(`.devdata/`)

**對現有資料的影響:🟢 不動。** 不碰 `app/`,不碰 migration;正式環境行為零變更。

### 驗收標準

1. `DEV_UNSAFE_LOCAL=1 .venv/bin/python tools/devserver.py` 起得來,
   `http://127.0.0.1:8080/upload/help` 看得到三張圖。
2. `/dev/login` 之後首頁是登入後的版型(側欄在,入口連結在最下面)。
3. 示範專案的建立版本頁看得到兩個版本號,其中一個標「草稿」。
4. 沒有 `DEV_UNSAFE_LOCAL` 時**拒絕啟動**。
5. 全套測試綠燈。

### 回滾方式

`git revert`;刪掉兩個新檔即可,`app/` 未被觸碰。

### 🐛 計畫沒想到的一層:gateway 剝前綴(第二條 5 回寫)

第一次跑起來截圖時,側欄的 **active 反白不見了**——首頁上「專案總覽」沒有變成藏青底。

**根因不在程式,在替身的落差:** 正式環境是 `portal-gateway` 把 `/upload/` 剝掉才轉給我們,
所以 app 收到的 path 是 `/`;而本機直接打 `/upload/`,app 收到的就是 `/upload/`,
`current_path == '/'` 永遠不成立。

**這正是「本機驗證」最危險的失敗模式:畫面看起來像壞的,而程式其實是對的。**
反過來也一樣成立——落差會讓人修一個不存在的 bug,或放過一個真的。

修法:devserver 加一層 `strip_prefix()` ASGI 包裝,行為與 gateway 一致
(`/upload/admin/users` → `/admin/users` + `root_path`;`/upload` → `/`;
前綴外的 `/dev/login` 不動)。三個案例都有測試。

⚠ 這與 T52 的教訓同型:**替身與真實行為的落差本身就是風險**,
當時是「假 IdP 的 token 永不過期」藏了 240 條測試都抓不到的缺陷。

### 遺留問題與後續建議

1. 本機的 `FakeOidc` token **不會過期**——續期(T52)那條路徑本機驗不到,仍靠 pytest。
2. 上傳檔案走 `FakeStorage`(記憶體),重啟就消失;要驗真的物件儲存還是得 `docker compose up -d`。
3. `.devdata/dev.db` 不會自動清掉;假資料改壞時直接刪掉整個目錄重跑。
