## 計畫(動工前寫,第二條 2)

### 目標

版本號由**內容區右上角**移到**側欄最底**(「回到平台入口」下方)。

Benny 實測回報(附截圖,箭頭由右上指向左下)。

### 現況為什麼長那樣(不是設計,是意外)

`app.css` 裡**沒有任何 `.app-version` 規則**。那個 `<p>` 是 `.layout`(`display:flex`)
裡的第三個 flex item,排在 `<main class="page">` 之後 —— 於是被擠到右上角。
「它現在的位置」從來沒有人決定過。

### 🔴 不能整個搬進側欄

側欄只有**已登入且已開通**的人看得到,而 T68 放版號的理由是
「**匿名 / 待開通 / 已開通三種狀態都看得到**」(使用者回報問題時報得出版本,
換版驗證也不必挑哨兵檔)。T81 就是為了保住這一點才把它從 `home.html` 搬到共用版型。

**整個移進側欄 = 匿名與待開通者再也看不到版號 = 把 T68 悄悄廢掉。**
這是本任務唯一真正的風險,所以做法是:

| 誰 | 版號在哪 |
|---|---|
| 已登入且已開通(有側欄) | **側欄最底**,入口連結下方 |
| 匿名 / 待開通(無側欄) | 維持現狀(共用版型的那一個),行為一字不變 |

🔴 **兩者互斥,不得同時出現** —— 同一頁印兩次版號,回報問題的人會不知道該報哪一個。

### 影響範圍

- `app/templates/base.html`(側欄加一行;原本那個 `<p>` 加條件)
- `app/static/app.css`(`.side-version`:小字、置底、與入口連結拉開一點)
- `tests/test_version_display.py`(新增位置與互斥的斷言)

**對現有資料的影響:🟢 不動。** 純模板與樣式。

### 驗收標準

1. 已開通者:版號在側欄,且**排在 `side-exit` 之後**(整個側欄最後一個元素)。
2. 匿名者仍看得到版號(既有測試維持綠)。
3. 🔴 同一頁**只出現一次**版號。
4. 全套測試綠。

### 回滾方式

`git revert`;純模板與樣式,無資料、無設定。


⚠ 另外兩條新測試(互斥、無側欄者仍看得到)**在實作前就是綠的** —— 它們釘的是
「不要在搬動時弄壞的東西」,不是新行為。這一點誠實標明:紅起步的只有位置那一條。

### 為什麼斷言「順序」而不是「頁面上有沒有」

`assert "v0.2.2" in body` 在版號還在右上角時**也會綠** —— 那種測試不會失敗,
所以也不會保護任何東西。這裡釘的是
`body.index("side-exit") < body.index("side-version") < body.index("</aside>")`。

🟢 **不動。** 純模板與樣式,無 migration、無查詢變更。
