# T96:專案短名(slug)自動產生

**建立日期:** 2026-08-24 16:50
**最後更新:** 2026-08-24 17:15
**版本:** v1.1
**任務編號:** T96

---

## 計畫(動工前寫,第二條 2)

### 目標

建立專案時**不再要求使用者填「專案短名(網址用)」**,由系統從專案名稱自動產生。

Benny 回報(附截圖):「專案短名(網址用) 改成自動幫專案產生」。

### 現況的問題

表單第一個欄位就是 `slug`,而且是必填 + `pattern` 限制
(3–64 小寫英數與連字號、不以連字號開頭或結尾)。使用者要建一個專案,
**第一件事是先想一個網址用的英文短名** —— 那是實作細節,不是他要做的事;
中文專案名的人尤其卡在這裡。

### 做法(三個判斷)

| 決定 | 理由 |
|---|---|
| 由**名稱**產生:`My Cool Tool` → `my-cool-tool` | 網址要看得懂,短名本來就是名稱的網址版 |
| 名稱無可用 ASCII(純中文)→ 退回 `p-<8 碼十六進位>` | 🔴 **不引入拼音套件**——那是新的執行期相依 + 供應鏈風險;本專案已有「自己寫 `markdown_lite` 而不引入 markdown + 消毒器兩個相依」的前例 |
| 撞名**自動加後綴**(`-2`、`-3`…),不回錯誤 | 欄位都拿掉了,再叫使用者「換一個短名」是叫他改一個他看不到的東西 |

### 🔴 slug 是永久的,而且在網址裡

本平台**沒有改名功能**,slug 一旦產生就會出現在別人貼出去的連結裡。所以:

- 產生規則必須**穩定**(同樣的名稱 → 同樣的 base),不能每次都亂數。
- 純中文名稱退回亂數短名是**已知的代價**:網址會是 `p-3f9c2a10` 這種不可讀的形式。
  這個代價寫在這裡,不藏在程式裡。願意的話,使用者仍可在名稱裡放英文。
- API(`POST /v1/projects`)**維持可指定 slug**(向下相容,而且腳本使用者要的正是
  可預測的短名);只是改為選填,不填就自動產生。

### 影響範圍

- `app/slugs.py`(新增:`slugify()` 與 `unique_slug()`)
- `app/schemas.py`(`ProjectCreate.slug` 改為選填)
- `app/routers/web.py`(建立專案:不再讀 slug 欄位;撞名自動換一個重試)
- `app/routers/projects.py`(API:未指定就自動產生)
- `app/templates/project_new.html`(移除 slug 欄位)
- `tests/test_slugs.py`(新增)

**對現有資料的影響:🟢 不動。** 既有專案的 slug 一字不改,無 migration。

### 驗收標準

1. 表單**沒有** slug 欄位;只填名稱就能建立專案。
2. `My Cool Tool` → `my-cool-tool`;純中文名稱 → 合法 slug(符合 `SLUG_RE`)。
3. 同名專案連建兩次 → 第二個自動變 `-2`,**使用者看不到任何錯誤**。
4. API 指定 slug 時行為不變(向下相容)。
5. 全套測試綠。

### 回滾方式

`git revert`;無資料異動,既有 slug 不受影響。

## 結果

### 異動檔案

| 檔案 | 改了什麼 |
|---|---|
| `app/slugs.py` | 新增:`slugify()` / `fallback_slug()` / `unique_slug()` |
| `app/schemas.py` | `ProjectCreate.slug` 改選填(空字串或 None = 請自動產生) |
| `app/routers/web.py` | 表單不再收 slug;撞名**自動換一個**重試三次;轉址改用實際寫入的 slug |
| `app/routers/projects.py` | API 未指定 slug 時自動產生(指定時行為一字不變) |
| `app/templates/project_new.html` | 移除短名欄位,名稱下方說明「短名會自動產生」 |
| `tests/test_slugs.py` | 新增 10 條 |
| `tests/test_web_upload.py` 等 5 支 | 既有測試對齊新契約(見下) |

### 測試(紅 → 綠)

```
# 紅(實作前)
9 failed, 1 passed        # tests/test_slugs.py

# 綠(實作後)
10 passed                 # tests/test_slugs.py
540 passed                # 全套(530 → 540)
ruff check .              # All checks passed!
```

### ⚠ 一條既有測試**換了契約**(不是放水,依 CI 紅線須說明)

`test_slug重複時回到表單並顯示訊息` → 改寫為
`test_同名專案不再回錯誤而是自動換一個短名`。

- **舊行為**:短名重複 → 回到表單顯示「已被使用」,讓使用者改那個欄位。
- **新行為**:表單已經沒有那個欄位了,所以自動加後綴(`-2`)。
- **仍然被釘住的東西一項未少**:不得丟一頁錯誤讓使用者重打。

另外 `test_表單回填的值有逸出` 的**觸發方式**改了:原本靠一個非法短名
(`"BAD SLUG"`),那條路徑不再存在,改用空白名稱觸發同一條錯誤路徑 ——
驗的東西(回填值必須逸出)一字未減。

其餘 5 支測試只是把「表單送 slug」改成「表單送名稱」,因為表單真的不再有那個欄位。
**刻意沒有讓端點偷偷接受畫面上不存在的欄位** —— 那會讓測試綠得毫無意義。

### 🔴 實測揭露的代價:中文名稱的網址不可讀

devserver 實建一個名為「示範中文工具」的專案:

```
/upload/projects/p-1ded8d7a
```

這是「不引入拼音套件」的直接後果,而**本平台的專案名多半是中文** ——
所以這不是邊緣案例,是常態。三個選項留給後續裁示(見「遺留問題」)。

### 對現有資料的實際影響

🟢 **不動。** 既有專案的 slug 一字不改,無 migration;API 向下相容。

### 遺留問題與後續建議

1. 🔴 **中文名稱 → `p-xxxxxxxx` 是常態而非例外。** 三個選項:
   ① 維持現狀(零相依,網址不可讀);
   ② 引入 `pypinyin`(純 Python、無 C 擴充)→「示範中文工具」變 `shi-fan-zhong-wen-gong-ju`
      ——代價是**新增執行期相依**(供應鏈、image 大小、平台鐵則的審查);
   ③ 表單留一個**選填**的英文短名欄位,空白才自動產生 —— 回到 T96 想解決的問題一半。
   **待 Benny 裁示,我不自行選 ②。**
2. slug 仍無改名功能。自動產生之後,「產生了不喜歡的短名」會比從前更常見 ——
   若要做改名,必須連同舊網址的轉址一起設計(不然別人貼出去的連結會死)。
