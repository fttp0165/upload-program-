### 為什麼專案已有四份文件了還需要這一頁

| 現有 | 回答的問題 | 為什麼不夠 |
|---|---|---|
| 任務表(160+ 列) | 每一項做了什麼、為什麼 | 太細。要從 160 列裡自己歸納「現在卡在哪」 |

| GitHub PR | 這一版的 diff 與 CI | 不含 staging 欠項、營運限制 |

四個都是對的,但**沒有一頁看得完**。

🔴 因此本頁明確寫成**摘要而非真相來源**:任何一格與任務表 / 日誌 / 索引衝突時,
**以那些為準**。這一條寫在文件開頭而不是結尾——若讀者把摘要當權威,
這一頁就會變成第五份會漂移的真相,那比沒有它更糟。

## 🐛 順手抓到的:`--check` 的盲點

彙整過程中順手看了一眼 `render_docs.py` 的 TARGETS,發現**前一天新建的
第 11 份申請書不在裡面**——它沒有 HTML 版,而其他兩份第九條文件都有。

而 CI 是**綠的**。

### 根因

`render_docs.py --check` 只掃它自己的 `TARGETS` 清單。
**漏掉的東西不在清單裡,清單當然檢查不出來。**
新建一份正式文件卻忘了加進 TARGETS,`--check` 會照樣印「All checks passed」。

這與 T117、T127 是同一個形狀:**檢查器只證明它檢查過的東西是對的**,
不證明「該檢查的都檢查了」。差別在於這次的漏網之魚是**文件**,
症狀比程式碼更難察覺——沒有 HTML 版不會有任何錯誤訊息,
只有對方收到 md 卻打不開時才會發現,而那時已經寄出去了。

### 為什麼這件事非補測試不可

第九條 7 自己寫過:「**規約若沒有測試,三個月後就是一句沒人記得的話**」。
這次是**人眼**發現的,而人眼下次不一定會看。

新測試 `test_登記在案的對外文件都有HTML版`:

- 🔴 判準綁在**索引**而不是 `glob`——索引是「哪些算跨專案文件」的
  **唯一登記處**(第九條 5)。綁 glob 等於讓規則散成兩份,而兩份遲早分岔。
- 以正規表示式讀 `render_docs.py` 原始碼而非 `import` 它:
  render_docs 需要 `markdown` 套件,而本測試檔其餘八條都不需要任何相依——
  為了一條測試把整檔綁上第三方套件不划算。

### 紅 → 綠

先寫測試,**紅**,而且錯誤訊息正好點名漏掉的那一份:

```
AssertionError: 對外文件已登記進索引卻沒有 HTML 版(請加進 tools/render_docs.py 的 TARGETS):
['upload-program_致_cats-portal_申請_CI容器網路開通Debian套件庫_20260826-0750.md']
```

補進 TARGETS 後轉綠。守門測試 8 → **9 條**。

## 為什麼不做成 Artifact 而是走 repo 的 md + HTML

憲法第四條 4 規定正式文件 md 與 HTML 並存,且第四條 6 明白要求
**HTML 由 `tools/render_docs.py` 自 md 產生**,理由就是「避免兩版人工同步而漂移」。

另開一份外部託管頁面等於再造一個**不由產生器管的第三版**——
正是第四條 6 要防的事。所以走既有機制:md 進版控當權威,
HTML 是單檔可離線開的發布版。

## 遺留問題與後續建議

1. **本頁需要人維護。** 摘要頁最典型的死法是「寫的時候很準,三週後全是舊資訊」,
   而**過期的狀態頁比沒有狀態頁更危險**(它看起來很權威)。
   建議的更新時機:**每次發版**、以及**卡關項狀態改變時**。
   ⚠️ 目前**沒有自動守門**能判斷內容是否過期——測試查得出檔案存不存在、
   抬頭齊不齊,查不出「§2 寫的還是不是現在的線上版本」。這一點誠實記著。
2. §2 的「線上狀態」寫的是**最後打出去的 tag**,不是遠端量測結果。
   要確認 VM 實跑版本仍須 `tools/smoke.sh --vm --expect vX.Y.Z`。
