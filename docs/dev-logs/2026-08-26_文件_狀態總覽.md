## 計畫(動工前寫妥)

### 目標

新增一份**常設現況文件** `docs/狀態總覽.md`(md + HTML 並存,憲法第四條),
以七節彙整專案現況,讓新加入者與回頭查看的人**一頁看懂**:

1. 系統定位與部署現況
2. 版本現況(三個版本號各在哪裡)
3. 里程碑與任務進度
4. 未完成任務與卡點
5. 平台整合狀態(SSO / SLO / gateway)
6. 測試與品質
7. 遺留問題與後續建議

檔名不帶日期——這是**往前看、持續更新**的常設清單類文件,帶日期會每天長出
一份新的、舊的繼續看起來像現況(同 cats-portal 憲法第四條 6 的教訓)。

### 影響範圍

🟢 純文件,不動程式行為、不動資料:

- 新增 `docs/狀態總覽.md` 與 `docs/狀態總覽.html`
- `tools/render_docs.py` 的 `TARGETS` 清單**加一行**(讓 HTML 由產生器產出,防兩版漂移)
- 本篇 dev-log

### 驗收標準

1. `docs/狀態總覽.md` 七節齊備,檔頭含建立日期/最後更新/版本,文末有版本歷史(第七條)
2. `docs/狀態總覽.html` 由 `python tools/render_docs.py` 產生(light 主題由產生器保證),
   `python tools/render_docs.py --check` 通過
3. 內容與 `docs/任務表.md` v1.75(2026-08-24 17:40)一致,不自創狀態
4. 文內明載「權威來源是任務表與 dev-logs,本文是總覽快照」,避免成為第二真相

### 回滾方式

`git revert` 本次 commit 即可:刪除兩個新檔、還原 `TARGETS` 那一行。無 migration、無資料影響。

## 結果(完工後補)

- 異動檔案:
  - `docs/狀態總覽.md`(新增,v1.0)
  - `docs/狀態總覽.html`(新增,由 render_docs.py 產生)
  - `tools/render_docs.py`(TARGETS 加入 `狀態總覽.md`)
  - 本篇 dev-log
- 為什麼這樣做:
  - 現況散在任務表「目前進度」節、CLAUDE.md、多篇 dev-logs;任務表已 1700+ 行,
    「現在到哪裡了」要翻很久。總覽文件收斂成一頁,並明載自己不是權威來源。
  - 捨棄的替代方案:①直接在任務表頂端擴寫——任務表已過長,且任務表的職責是
    任務追蹤不是對外總覽;②寫進 README——README 面向使用者,不面向維運/開發現況。
- 測試結果:`python tools/render_docs.py --check` 通過(見下方紀錄)。
  純文件變更,不跑 pytest 全套(憲法第三條 4:不動程式行為)。
- 對現有資料的實際影響:🟢 無。
- 遺留問題:本文之後**每次任務表「目前進度」節更新時應同步更新**,否則會變成
  過期快照;文內已標示以「最後更新」時間判斷新鮮度。
