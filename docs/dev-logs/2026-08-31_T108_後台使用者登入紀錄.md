## 計畫(動工前寫,第二條 2)

### 需求

Benny:「後台 新增使用者登入 紀錄」。

### 盤點:哪些已經有了(先查再做,不然會做出第二套)

| 已有 | 在哪裡 |
|---|---|
| `users.last_login_at` 欄位,每次 callback 成功就更新 | `models.py:123`、`auth.py` |
| 稽核表 + 後台稽核頁(可依 action 篩選) | `audit.py`、`/admin/audit` |
| 「停用帳號登入被拒」只寫 `log.info` | `auth.py` |

🔴 **所以缺的不是儲存,是兩件事:**
1. **登入這件事沒有進稽核** —— `last_login_at` 只留「最後一次」,
   而「這個帳號這個月登入過幾次、上一次是什麼時候」查不出來。
   稽核表本來就是回答「誰在何時做了什麼」的地方,登入卻不在裡面。
2. **後台看不到 `last_login_at`** —— 欄位存了兩個月,一個畫面都沒顯示過。

### 做什麼(🟢 零 migration)

1. 新增稽核動作 **`user.login`**,在 callback 成功建立 session 時記一筆。
2. 新增 **`user.login_denied`** —— 停用帳號嘗試登入。
   🔴 這一條比成功登入更值得記:離職者的 IdP 帳號若沒被停用(契約 §1.1 明載
   「離職不會自動停用」,deny-by-default 是第二道防線),**他仍然登得進 IdP**,
   只是被我方擋下。那件事目前只留在 stdout log 裡,而 log 會滾掉。
3. 後台使用者頁每個帳號顯示 **最後登入時間**;從未登入顯示「從未登入」。

`action` 欄位是 `String(64)` 而非 DB enum(`models.py:308` 寫明「刻意讓新增動作
不需要 migration,因為阻力會讓人選擇不記」),所以 1、2 兩項**零 migration**。
稽核頁的動作篩選清單來自 `sorted(a.value for a in AuditAction)`(`web.py:1170`),
新動作**自動出現**,不必改頁面。

### 🔴 契約紅線(這件事最容易踩的地方)

稽核只記 **`actor_id`(本地 user id)**,不記 email、不記姓名。
- `target_label` 依 `models.py:290` 的註解「只放識別用字串」——登入事件留空。
- 姓名只在**後台頁面**由 `display_name_cache` 顯示(§4.2a L1 第 3 條:僅供管理後台),
  **不進稽核內容、不進 API**。
- **不記 IP。** ⚠ 這是刻意的取捨,寫下理由:稽核表目前一個網路識別欄位都沒有,
  為登入單獨加一個 IP 欄位要 migration,而且 IP 在本平台是**個資**(對內網而言
  幾乎等於指名道姓)。要記 IP 應該是全表一致的決定,不是夾在這個任務裡開一個特例。
  需要時再另立任務,連同保留期一起想。

### 影響範圍

- `app/audit.py`(兩個新動作)
- `app/routers/auth.py`(兩處 `record()`)
- `app/templates/admin_users.html`(顯示最後登入)
- `app/routers/web.py`(待開通清單那組也要傳得到 `last_login_at` —— 確認現有 context 夠用)
- `tests/test_login_audit.py`(新增)

**對現有資料的影響:🟢 不動、無 migration。**

### 驗收標準(先寫會失敗的測試)

1. 🔴 登入成功寫下一筆 `user.login`,`actor_id` 是該使用者(紅起步)
2. 🔴 停用帳號登入被拒時寫下 `user.login_denied`(紅起步)
3. 🔴 登入稽核**不含 email**(反向驗證紅線;`target_label` 為空)
4. 🔴 後台使用者頁顯示最後登入時間(紅起步)
5. 從未登入的帳號顯示「從未登入」而不是空白或 `None`(守門)

### 回滾方式

還原三個檔案。🟢 無 migration;已寫下的稽核列留著無害(保留期工具會處理)。

## 結果

### 異動檔案

| 檔案 | 改了什麼 |
|---|---|
| `app/audit.py` | 新增 `user.login` 與 `user.login_denied` |
| `app/routers/auth.py` | callback 成功 / 停用被拒各記一筆 |
| `app/templates/admin_users.html` | 「其他帳號」每列顯示最後登入或「從未登入」 |
| `tests/test_login_audit.py` | 新增 7 條 |

⚠ **待開通清單刻意沒改**:那裡已經顯示「申請於 {created_at}」,而待開通者的
建立時間**就是**他第一次登入的時間(首登才建列)。再加一個「最後登入」只會出現
兩個幾乎一樣的時間,讓管理員多讀一次才發現它們是同一件事。

### 測試(紅 → 綠)

七條裡**六條紅起步**:

```
FAILED test_登入成功寫下稽核
FAILED test_停用帳號登入被拒也要留痕
FAILED test_後台使用者頁顯示最後登入時間
FAILED test_從未登入的帳號顯示從未登入
FAILED test_新動作在字彙表裡[user.login]
FAILED test_新動作在字彙表裡[user.login_denied]
PASSED test_登入稽核不含email與姓名        ← 沒有稽核就當然沒有 email(見下)
```

⚠ **最後那條一開始就是綠的,而它是假綠**:當時根本沒有登入稽核事件,
迴圈跑零次,斷言等於沒執行。加上功能之後它才真的在驗東西 ——
**這種綠燈比紅燈危險**,所以寫在這裡。

修完:`7 passed`;全套 **590 passed**(583 → 590)、`ruff check` 乾淨。

### 對現有資料的實際影響

`models.py:308` 的註解早就為這件事鋪好路(「阻力會讓人選擇不記」)。

### 遺留問題與後續建議

1. ⚠ **沒有記 IP,這是刻意的。** 稽核表目前一個網路識別欄位都沒有;為登入單獨
   加一個要 migration,而 IP 在內網幾乎等於指名道姓。要記應該是**全表一致**的
   決定,連同保留期一起想,不該夾在這個任務裡開特例。
2. 🔴 **`artifact.upload_rejected`(T107)與 `user.login_denied` 現在都有資料了,
   但沒有人在看。** 兩者是同一類東西:「被防線擋下的嘗試」。稽核頁能篩 action,
   但沒有「同一個人短時間內反覆被擋」的訊號。建議另立任務做一個小的
   **異常訊號區塊**(放在管理總覽的「需要處理」下方),一次涵蓋兩者 ——
   分開做會變成兩個半套的視圖。
