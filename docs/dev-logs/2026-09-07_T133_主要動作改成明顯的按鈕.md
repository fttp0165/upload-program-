## 計畫(動工前寫,第二條 2)

### 需求

Benny(附截圖,紅框框住專案頁底部那一行):「按鈕不明顯改成,明顯的按鈕」。

現況是兩個**純文字連結**,中間一個 `·`:

```html
<p class="history-link">
  <a href="…/releases/new">建立新版本</a> ·
  <a href="…/releases">查看版本歷史 →</a>
</p>
```

專案頁上唯一「往下走」的動作,長得跟內文連結一樣。截圖裡那個專案
(`key-word-serach-v88-2`)**還沒有任何版本**,而「建立新版本」正是它此刻唯一該做的事。

### 🔴 盤點時發現的:把它變醒目會放大一個既有缺陷

`history-link` 那一段**沒有任何權限判斷** —— viewer 也看得到「建立新版本」,
點進去會 403(`may_manage_releases` 要求 maintainer 以上)。

現在它不明顯,所以這個缺陷的代價很小。**一旦做成醒目的主要按鈕,
它就從「不明顯的連結」變成「醒目的陷阱」** —— 版面上最搶眼的東西,
按下去告訴你沒有權限。

所以本任務**不是純樣式改動**,必須連權限一起修。`can_edit`
(owner / admin / maintainer)已經在這一頁的 context 裡,與 `may_manage_releases`
是同一條界線,不必新增旗標。

### 做什麼

| 元素 | 現在 | 改成 | 條件 |
|---|---|---|---|
| 建立新版本 | 文字連結 | **主要按鈕** `.btn` | 🔴 `can_edit` 才顯示 |
| 查看版本歷史 | 文字連結 | 次要按鈕 `.btn .btn-quiet` | 讀得到專案的人都看得到 |

⚠ **刻意不動的東西**(範圍控制,理由寫下來):

- **「取消」一律維持文字連結**(`project_new.html`、`release_new.html`)——
  取消不該與主要動作等重;兩個一樣重的按鈕會讓人停下來讀字。
- **「← 回專案頁」「清除篩選」「我的回報」維持文字連結** —— 那些是導覽不是動作。
- **管理總覽裡的專案名連結不動** —— 那是內文連結,變按鈕會讓清單變成一片色塊。

### 影響範圍

- `app/templates/project.html`(那一段)
- `app/static/app.css`(`.history-link` 改為按鈕列的間距)
- `tests/test_web_project.py`(新增)

**對現有資料的影響:🟢 不動、無 migration。**

### 驗收標準(先寫會失敗的測試)

1. 🔴 maintainer 以上看到的「建立新版本」帶按鈕樣式(紅起步)
2. 🔴 **viewer 看不到「建立新版本」**(紅起步——這是本任務真正的修正)
3. viewer 仍看得到「查看版本歷史」(守門:別把讀得到的人一起擋掉)
4. 兩個動作都指向原本的網址(守門:改樣式不得改行為)

### 回滾方式

還原兩個檔案。🟢 無資料變更。
