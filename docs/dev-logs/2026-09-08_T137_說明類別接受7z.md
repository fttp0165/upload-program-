## 計畫(動工前寫,第二條 2)

### 起因

Benny:「說明改 .7z 也可以」。

現況(`app/filetypes.py` 的 `_ALLOWED`):

| 格式 | 說明(doc) | 程式碼(source) | 執行檔(binary) |
|---|---|---|---|
| `.zip` | ✅ | ✅ | ✅ |
| `.7z` | ❌ | ✅ | ✅ |

⚠ **「說明」原本允許 zip 不是為了讓人塞壓縮包** —— 是因為 `.docx` / `.odt`
本質就是 zip(程式碼註解寫著 `# docx / odt`)。

🔴 **但這件事說服我照做,理由不是「使用者要求」而是「拒絕 7z 站不住腳」:**
`.docx` 已經讓「說明」可以收一個**外面看不出內容的壓縮容器**了。
既然 zip 進得來,擋 7z 擋掉的不是風險,只是**一種格式** ——
而使用者拿到的錯誤訊息會說「這一格不收 7z」,他下一步就是把 7z 轉成 zip,
風險完全一樣,只是多繞一圈。**規則要能講出理由,講不出來的規則只會被繞過。**

### 為什麼這不放寬任何實質安全性

被放寬的只有 `_ALLOWED[doc]` 多一個 MIME。**三道紅線一個字沒動:**

1. `_ALWAYS_REJECT_PREFIXES`(`text/html` / `image/svg+xml`)—— 仍然**在任何
   kind 都擋**,那才是「不讓上傳內容在本服務網域被瀏覽器執行」的那道線。
2. 判型仍然只看 **magic bytes**,不信副檔名、不信前端送的 Content-Type。
3. 下載仍然一律 `Content-Disposition: attachment` + `nosniff`。

換句話說:7z 進來之後,它與已經能進來的 `.docx` **在本服務裡的待遇完全相同** ——
存起來、算 SHA-256、標 `not_scanned`、下載時強制當附件。

### 做什麼

1. `app/filetypes.py`:`_ALLOWED[ArtifactKind.doc]` 加 `application/x-7z-compressed`
2. `app/routers/releases.py`:「說明」卡片的 hint 補上壓縮檔
   —— 🔴 **不改這一行的話,畫面上寫著「PDF / Markdown / 文字檔」而它其實收 7z**,
   使用者不會去試一個看起來不被接受的東西,等於做了但沒人知道

### 影響範圍

**對現有資料的影響:🟢 不動、無 migration。** 只多允許一種型別,既有檔案不受影響。

### 驗收標準(先寫會失敗的測試)

1. 🔴 7z 檔頭以 `doc` 上傳 → 通過(現在會失敗)
2. 🔴 **反向:HTML 仍然在 `doc` 被擋**(守門:放寬的是一種格式,不是那道線)
3. 🔴 **反向:ELF 執行檔仍然不得以 `doc` 上傳**(白名單仍然是白名單,不是全開)
4. 「說明」卡片的 hint 提到壓縮檔

### 回滾方式

還原兩個檔案。🟢 無資料變更。

### ⚠ 施工中抓到兩件自己寫的東西

**① HTML 那條守門的第一版是假綠。**
它只斷言「被擋」+ mime 是 `text/html`。拿掉 `_ALWAYS_REJECT_PREFIXES` 之後
**它照樣綠** —— 因為白名單本來也沒有 `text/html`,HTML 會被**另一條規則**擋掉。
它證明的不是它自稱要證明的那件事。改成斷言錯誤訊息裡有「**瀏覽器**」
(那句話只從無條件拒絕那條路徑出來)之後才真的釘住那道線。

🔴 **這是第六種形狀:斷言問的是「結果對不對」,而該問的是「對的原因對不對」。**
在有**兩條規則都會導致同一個結果**的地方,只驗結果的守門會在其中一條被拆掉時
繼續發綠燈。

**② 反向驗證本身也會壞掉,而症狀跟假綠一模一樣。**
第一次驗「ELF 仍被擋」時我用
`s.replace('        "application/x-7z-compressed",\n', ..., 1)` 插旗標 ——
而 `x-7z-compressed` 在 `binary` / `source` / `doc` **三個區段都有**,
`,1` 打到的是**第一個(binary)**。binary 本來就收 ELF,所以什麼都沒變,
結果印出 `22 passed`。

🔴 **「改壞了但測試還是綠」與「根本沒改壞」在畫面上長得一樣。**
差別是後者連 `test_kind白名單` 這條既有測試也沒紅 —— 那才是看出來的線索
(要改壞的東西如果真的壞了,**通常不只一條會紅**)。改用只出現一次的
`"application/pdf",` 當錨點後,兩條同時紅,才算驗過。

### 對現有資料的實際影響

🟢 **不動。** 無 migration、`.env` 無新變數。既有檔案與其判型結果完全不受影響。

### 遺留問題與後續建議

1. ⚠ **「說明」現在的壓縮格式是 zip + 7z,但 `.tar.gz` / `.xz` / `.bz2` 仍被擋。**
   那是照 Benny 指示的範圍(只加 7z)。🔴 **但這個不對稱會咬人**:
   拿 `.tar.gz` 的人得到的錯誤訊息會列出允許的型別,而他看到 zip 與 7z 都行、
   偏偏 gz 不行,**講不出理由** —— 與本任務放寬 7z 的理由是同一個。
   要不要一併放寬,待裁示。
2. ✅ **`/help` 的類別對照表已同步**(`help.html` 的 doc 那列補上「zip/7z 壓縮檔」)——
   🔴 這一頁與卡片提示是**兩個**會說謊的地方,漏掉任一個都會讓使用者以為不能傳。
   ⚠ `_help_diagrams.html` 的 SVG 寫的是 source 那格的格式,無需改(已檢查)。
