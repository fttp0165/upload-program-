## 計畫(動工前寫,第二條 2)

### 目標

Benny:「發 0.3.2」。本版內容:**T137**(「說明」接受 .7z)+ **T138**(單檔上限 200 MB)。

### 為什麼是 patch 版而不是 0.4.0

兩個任務都**只放寬既有行為**:原本傳得上去的一樣傳得上去、原本被擋的仍然被擋
(HTML / SVG、magic bytes、attachment + nosniff 三道紅線一字未動)。
沒有任何既有行為改變語意 —— 對照 v0.3.0 之所以升次版號,是因為
`publish` 從「發布」變成「送審」,**那才是會讓看 Release 頁的人誤判的改動**。

### 做什麼

1. `app/version.py`:`APP_VERSION` → `0.3.2`(🔴 第八條 4:**打 tag 之前**)
2. `docs/狀態總覽.md`:依 **v2.0 立下的規矩**「發版任務一律連同本頁回寫」
3. `docs/任務表.md`:T139 一列 + 版本歷史

### 🔴 這一版的部署有一件與往常不同的事:gateway 已經先動過了

`GW-UPLOAD-256M` 已於 2026-09-08 10:36 在 VM 套用(reload,零停機,五條路由全通)。
也就是說**換版之後 200 MB 才會真的生效** —— 順序是對的(gateway 先寬永遠安全),
但換版驗證必須包含一項往常沒有的:**傳一個 >128 MB 的檔,不得出現 nginx 的 413 錯誤頁。**

⚠ 而 `proxy_*_timeout` 維持 150s 的判斷(GW 那篇的遺留 3)**尚未被大檔實測驗證**,
這一版換版就是驗它的機會。

### 影響範圍

**對現有資料的影響:🟢 不動、無 migration、`.env` 無新變數。**

⚠ **但 VM 的 `.env` 若明寫了 `MAX_ARTIFACT_BYTES=104857600`,它會蓋掉程式預設。**
🔴 換版前必須確認 —— 這是本版唯一會讓「換了版卻沒生效」的地方,
而症狀是**上限仍是 100 MB 但沒有任何錯誤訊息**。

### 驗收標準

1. `APP_VERSION == "0.3.2"`,全套 671 綠、`ruff` 乾淨
2. 狀態總覽無任何一句與現況衝突
3. 換版後:容器自報 `0.3.2`;傳 >128 MB 的檔**不得**看到 nginx 的錯誤頁

### 回滾方式

退回 v0.3.1 的 image 即可,🟢 無 migration。
⚠ gateway 的 256m **不必跟著退** —— 比較寬永遠是安全的方向。

### 遺留問題與後續建議

1. 🔴 **換版前先確認 VM 的 `.env` 沒有明寫 `MAX_ARTIFACT_BYTES`** ——
   有的話它會蓋掉程式預設,而症狀是**上限仍是 100 MB 且沒有任何錯誤訊息**。
   這是本版唯一會造成「換了版卻沒生效」的地方。
2. 🔴 **換版驗證要加一項:傳一個 >128 MB 的檔,不得出現 nginx 的 413 錯誤頁。**
   同時這是驗 gateway 那邊「`proxy_*_timeout` 維持 150s」那個尚未被大檔驗證過的判斷。
3. ⚠ **T105 仍未做**(`APP_VERSION` 不得 ≤ 最新 tag 的 CI 守門)——
   v0.2.4 事故的結論至今靠人工 grep。**這是第三次在發版時記下同一件事。**
4. ⚠ **cats-portal 那條分支尚未合併**,而 VM 的 `/opt/cats-portal` 停在該分支上。
   合併後要把 VM 切回 main 並重跑 `ops/gateway-apply.sh --check`,
   否則下一個人在 VM 上 `git pull` 會拉到分支的更新卻以為自己在 main。
