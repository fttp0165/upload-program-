### ⚠ 撞到一條既有紅線,而處理方式是具名例外不是放寬斷言

`test_專案頁所有連結帶前綴且無絕對網址`(T53 那條)紅了 ——
因為「固定連結」**刻意**是絕對網址。

🔴 **沿用 T51 的前例**(當時 `/account` 撞同一條紅線):
**加一個具名例外,不放寬斷言**,而且**例外自己有測試**
(`test_固定連結是可點的絕對網址` 釘住它必須以 `public_base_url` 開頭,
所以「絕對」不會變成任意)。

例外的範圍收到最小:只認 `class="permalink"` 的 `<a>`。
並加一句 `assert permalinks`(**例外的對象消失時要紅**)——
否則哪天固定連結被拿掉,這個例外會變成一個沒人記得的破洞。

✅ **實測那條斷言仍然咬得動:** 故意把「下載」按鈕改成絕對網址 → **紅**。

### ⚠ 我自己寫的反向斷言第一版咬到了自己

`test_專案頁不得出現裸位元組` 第一版直接對整份 HTML 掃 `\d{7,}\s*bytes`,
結果咬到**我刻意留的 `title` 提示**(精確值 hover 才出現,那是設計)。

🔴 **修法是讓斷言符合它自己宣稱的意圖**(「**畫面上**不該出現裸位元組」)——
剝掉標籤只掃文字節點,**而不是放寬正則**。放寬會讓它連 inline 的違規一起放過,
那整條就廢了。剝標籤之後它仍然咬得動 inline 違規(上表 BREAK 1 已證明)。

📌 這是本 repo 反向斷言的第 N 次同一課:**「它紅了」有兩種可能 ——
程式錯了,或**斷言問錯了問題**。分不出來的時候,去看它宣稱要證明什麼。
