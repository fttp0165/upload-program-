## 計畫

### 目標

讓 portal 後台的「+ upload」/「✓ upload」開關**就是**本服務的開通開關:

| action | 對方庫裡狀態 | T146(舊) | **T147(新)** | 稽核 |
|---|---|---|---|---|
| `join` | 不存在 | 建 pending | **建 active** | `user.provision` + `user.activate` |
| `join` | pending | 不動 | **→ active** | `user.activate` |
| `join` | disabled | 不動 | **→ active** | `user.activate` |
| `join` | active | 不動 | 不動 | 無 |
| `leave` | active / pending | 忽略 | **→ disabled** | `user.disable` |
| `leave` | disabled / 不存在 | 忽略 | 不動、**不建列** | 無 |

不變的:四層驗證、只收三個欄位、冪等、**名字與信箱一個欄位都不碰**、
`platform_role` 不碰(推送只管「能不能用」,不管「是不是本服務管理員」)。

### 🔴 兩條必須一起改

只改 join 不改 leave = **開得了、關不掉**(portal 取消開通後那個人仍能用)。
本任務兩條同一次 commit。

### 🔴 新增的防線:不得停用最後一位本服務管理員

`leave` 若打到本服務**唯一一位 active 平台管理員** → **409**,不動。
否則 portal 端一個點擊就能讓本服務沒有任何人進得了後台(與 `admin.patch_user`
「不能停用自己」同一個理由)。409 會在 portal 畫面上顯示成推送失敗 —— 那正是要的效果。

### 取捨(寫清楚,不藏)

1. **本服務管理員手動停用的人,portal 一按 join 就會被重新開通。** 本服務沒有欄位區分
   「誰停用的」;Benny 的裁示是 portal 為準,故接受。若日後要區分,需加欄位(🟡)另立任務。
2. **T63「`/svc/upload` 只讀不判」不受影響**:那條管的是**登入 token 的 groups**,
   本任務改的是**推送**。登入時仍不看 groups,`test_groups_claim.py` 四條維持原樣。
3. 本服務後台的開通/停用按鈕**保留**(推送沒上線前的唯一路徑,也是推送失敗時的補救)。

### 影響範圍

| 系統 | 影響 |
|---|---|
| upload-program | 🟢 不動 schema、無 migration;執行期 UPDATE `users.status`(與後台按鈕相同的寫入) |
| portal | 🟢 旗標仍 off,未發版前無任何請求;回函需升 v1.1 告知語意改變 |

### 驗收標準

1. 上表六種情境各一條測試;
2. leave 打最後一位 admin → 409 且狀態不變;還有第二位 admin 時 → 照常停用;
3. join / leave 都不碰名字、信箱、`platform_role`;
4. 冪等:join/leave 各重送一次,第二次不再寫稽核;
5. T146 的四層驗證與 payload 測試全部維持綠;全套綠、ruff 乾淨。

### 回滾方式

`git revert` 本任務 commit,回到 T146 語意。無 migration。
已被推送開通/停用的人,狀態由本服務後台手動調回。
