# 裁決:擴大顯示名稱快取的用途(upload-program 申請)

**建立日期:** 2026-08-31 16:00
**最後更新:** 2026-08-31 16:00
**版本:** v1.0
**裁決方:** cats-portal / Platform(Benny)
**申請方:** upload-program
**來文:** 《申請:將顯示名稱快取的用途擴大至「專案頁擁有者辨識」》v1.0(2026-08-12 19:30)

---

## 0. 裁決

# ✅ 准

依申請書 §5 的建議稿寫進契約 **§4.2a L1 第 3 條**,並**加一條申請書沒寫的限制**
(見 §2)。契約已升 **v3.4**。

⚠ **本裁決是通則調整,不是給 upload-program 的具名特例** ——
所有 App 一體適用,不需逐案申請。理由與 2026-07-30 那次相同:
§4.2a 的存在本身就是為了避免「預設拒絕但誰問誰有」。

---

## 1. 准的是什麼

| 欄位 | 原本 | 現在 |
|---|---|---|
| 可快取 | `name` | **不變** |
| 來源 | 僅本人登入時的 ID token | **不變** |
| 同步 | 每次登入覆寫、無背景同步 | **不變** |
| **用途** | **僅管理後台顯示** | 管理後台 **+ 專案 / 版本 / 內容頁的擁有者、作者、上傳者辨識** |
| 授權判定 | 不得作依據 | **不變** |
| log | 不得進入 | **不變** |
| 清除 | 須可整批清除 | **不變** |

🔴 **放寬的是「顯示在哪」,不是「存什麼」或「給誰」。** 八項條件裡只有第 3 項動了。

## 2. 加了一條申請書沒有寫的限制

> **不得再散布至本服務以外**(不寄信、不匯出、不轉發)。

申請書寫了「不進 API 回應」,那擋住的是**程式取用**;但沒有擋住
「HTML 頁面上的名字被人另存、匯出成報表、貼進信件」這條路。
⚠ 這不是懷疑申請方,是把界線寫在條文裡而不是靠自律 ——
**能顯示** 與 **能帶走** 是兩件事,而契約只該許可前者。

## 3. 為什麼准(理由要留下來,否則下次會被當成先例濫用)

1. **原本的範圍是申請方自己畫的,不是本契約推導出來的。**
   2026-07-29 那份申請書把用途縮到「僅後台」以便評估 ——
   當時那是好的判斷,但它從來不是一條有獨立理由的紅線。
2. **內容頁天生要回答「這是誰做的」。** 在「業務庫只存 `sub`」之下,
   那個問題的答案是一串 UUID。**使用者看到「由 3f7a1c2e… 建立」等於沒看到**,
   而那不是資訊揭露的謹慎,只是一個沒有用的欄位。
3. **不放寬的實際後果不是「姓名沒有外流」,是各 App 自己找路。**
   §4.2a 本文早就寫過同一個論點:禁止受控的快取不會讓個資消失,
   管理員會改用便條紙記一份「誰=哪串 UUID」。同樣的力量在這裡也成立。

## 4. 誠實記載:這件事的代價

姓名從「只有管理員看得到」變成「站內所有登入者看得到」。

- 在**內部協作平台**上這是預期行為(GitHub、GitLab 皆如此),而本平台的
  對外邊界是單一 hostname + 需登入,不是公開網站。
- 🔴 但它確實**擴大了可見範圍**,而且**不可逆** —— 頁面上出現過的名字,
  已經被看過的人記住了。
- ⚠ 因此明載:**本條是許可,不是義務。** 不同意這件事的 App
  可以自己不顯示,契約不要求任何人顯示姓名。

## 5. 對各 App 的意義

| App | 影響 |
|---|---|
| **upload-program** | 可把專案頁 / 版本頁的 `sub` 前 8 碼換成顯示名稱(本申請的目的) |
| **PLM** | §6.1 的具名特例仍比通則寬,**不受影響**;不需要改用本條 |
| **sporton_core / compliance / SENSE_upload / survey** | 同樣得依本條顯示,**但不必做** |
| **portal-admin** | 原本就在後台範圍內,無變化;其四條額外約束(含停用即清除)不變 |

## 6. 不准的部分(申請書自己排除的,一併確認)

- ❌ Admin API 或任何新的 IdP 權限 —— 維持禁止(§4.2a 第 1 條)。
- ❌ 名字進 JSON API 回應 —— 維持禁止。
- ❌ 顯示 email 或 `preferred_username` —— 維持禁止(email 走 L1b,且 L1b 明文
  **不得顯示在任何頁面**,本裁決**不動 L1b 一個字**)。
- ❌ 新增資料庫欄位 —— 不需要,快取欄位早已存在。

🔴 **特別點出:L1b(通知用信箱)完全不受本裁決影響。**
信箱與姓名的處境不同 —— 姓名回答「這是誰做的」,信箱回答「怎麼聯絡他」,
後者放上頁面沒有任何業務理由,只是外洩面。
