2. 🔴 我方在貴方轄區做的兩項操作(請 commit 回權威 repo)

貴我雙方目前由同一位操作者執行,以下改動已直接在 VM 生效, 但權威 repo(cats-portal)還沒有這兩個變更——不補 commit 就是現場與 repo 漂移, 下次有人照 repo 重建 gateway 會把它們蓋掉:

2.1 解除 /upload/ 三個 location 的註解

gateway/nginx/conf.d/default.conf:location = /upload、/upload/static/、 /upload/ 三個區塊已解除註解(內容未動,與貴方備妥的版本一致)。 現場留有備份 default.conf.bak-* 與 default.conf.pre-upload。 ⚠️ 貴方有一條 CI 斷言釘住「容器上線前不得啟用」——commit 時要一併更新, 否則貴方自己的 CI 會紅。

2.2 🔴 修正 gateway 的 TLS 憑證(影響全平台,不只我方)

發現:ssl_certificate 原指向 /etc/nginx/certs/server.crt——那是一張 CN=sportonhr1cb 的自簽憑證(舊機器時代的遺留),不是 catsapp 的憑證。 所有使用者(含 PLM、sporton_core)一直拿到這張錯憑證;瀏覽器的「不安全」警告 有一半是它造成的(另一半是 client 端未安裝 catsRootCA)。

修正:catsapp.fullchain.crt / catsapp.key 已從 ~/cats-ca/ 複製到 gateway/nginx/certs/,default.conf 的 ssl_certificate/ssl_certificate_key 兩行已改指過去(sed 自動備份 default.conf.bak-cert),nginx -t 通過後 reload。 驗證:openssl s_client 現在回 subject=CN=catsapp.sporton.com.tw、issuer 為 RootCA。

請貴方:把憑證檔與 conf 變更 commit 回權威 repo,並評估是否公告 (已裝 catsRootCA 的使用者,瀏覽器警告會消失;行為變化雖是好事,仍值得知會)。

3. 三項回饋建議

# 發現 建議
1 🔴 cats-edge 內 catsapp.sporton.com.tw 別名掛在 keycloak(只聽 8080)。任何容器對正式網域打 HTTPS 都是 Connection refused——我方 OIDC discovery 就是這樣掛的,現以 extra_hosts: host-gateway hairpin 繞過 把別名改掛 portal-gateway(它聽 443 ssl):所有 App 在 cats-edge 內直連即通、憑證與對外一致,各 App 不必自備 hairpin。改掛後通知我方,即可移除 workaround
2 施工單 §2.1 靜態檔區塊的說明註解寫「不加尾斜線 → 保留 /upload/static/ 前綴交上游」,但實際指令 proxy_pass ...:8080/static/; 是剝前綴(帶 URI 替換)。指令正確(實測 app.css 200),是註解文字寫反 修正該行註解,免得下一個照著註解讀的人誤會
3 secret 交付檔內有多個變數,我方第一次抓錯(取到另一個 64 字元的值),症狀是「授權碼交換失敗」401,查了一輪才定位 交付檔內註明哪個變數是 client secret,或檔案只放必要變數

4. 我方側的透明揭露:bootstrap 缺陷(已修)

我方「待開通頁顯示自己的 sub」的自助流程(貴方已採納入契約 §4.3)有一個 我方自己的實作洞:bootstrap 清單原本只在建號時生效,而自助流程保證帳號 會先以 pending 存在——第一個管理員升不了級,現場以 SQL 解鎖。 已修並已於同日隨 v0.1.1 發布上線(pending 帳號在清單內時登入即升級; disabled 不升;含 8 條測試)。契約 §4.3 引用此做法的段落建議補一句: 「實作須讓清單對『已存在的 pending 帳號』也生效」,免得下一個照契約做的 App 複製同一個洞。
