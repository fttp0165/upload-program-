# 設計:發布者自行設定查看權限

**建立日期:** 2026-08-25 10:00
**最後更新:** 2026-08-25 10:40
**版本:** v1.1
**對應任務:** T100

---

## 1. 需求

Benny:「發布者可以設定使用者查看權限」+「**ADMIN 則都可以看到**」。

裁示(兩題):

| 題目 | 裁示 |
|---|---|
| 怎麼指定要加的人 | **輸入名字搜尋** |
| 角色種類 | **沿用現有三種**(owner / maintainer / viewer) |

## 2. 現況盤點

| 需求 | 施工前 |
|---|---|
| 資料模型有可見性(internal / private) | ✅ `Project.visibility` |
| 資料模型有成員與三種角色 | ✅ `ProjectMember` + `ProjectRole` |
| private 僅成員可讀、非成員 **404 而非 403** | ✅ `require_project_read()` |
| **ADMIN 看得到全部** | ✅ **已經成立**(`security.py` 的 `or identity.user.is_admin`、`queries.py` 的 `if user.is_admin`) |
| 成員管理 API | ✅ `PUT/DELETE /v1/projects/{slug}/members`(owner 才可) |
| 稽核動作 | ✅ `member.set` / `member.remove` 早就在字彙表裡 |
| **網頁上的成員管理介面** | ❌ **沒有** —— 只能打 API |
| **可見性切換介面** | ❌ 沒有(只能在建立時選) |
| 「ADMIN 都看得到」的**測試** | ❌ **沒有** —— 這條行為只靠實作的一行活著 |

🔴 **兩個發現決定了這個任務的形狀:**

1. **權限模型與 API 都已經齊備**,缺的是**介面**。從零設計一套權限會做出第二套規則,
   而兩套規則遲早分岔 —— 那是 private 專案外洩的典型起點。
2. **「ADMIN 都可以看到」已經是現況,但沒有測試。** 使用者明確要求的行為
   卻沒有守門,等於下一次有人「優化」那行條件時不會有任何東西攔住他。

## 3. 做法

### 3.1 介面(專案頁新增「查看權限」區塊,owner 可見)

- **可見性**:`internal ↔ private` 的下拉 + 儲存
- **成員清單**:顯示名稱(L1 快取)或截斷識別碼 + 角色 + 移除鈕
- **加人**:🔴 **純 HTML 的 GET 搜尋表單**(`?member_q=…`)→ 候選最多 5 筆,
  每筆兩個按鈕(加為 viewer / 加為 maintainer)

  為什麼不用 JS 即時搜尋:本專案的表單一律「純 HTML、不需要 JS」
  (CSP `default-src 'self'` 擋 inline script,而 T44 的決策是表單零 JS)。
  GET 表單回同一頁是最貼近既有風格、也最不會壞的做法。

### 3.2 搜尋端點的約束(這是本任務唯一的新外洩面)

「輸入名字搜尋」等於讓**任何專案擁有者**查得到其他同仁的存在。裁示已接受這個代價,
但要把它收到最小:

| 約束 | 理由 |
|---|---|
| 🔴 `q` 至少 1 個字,**空白不列全部** | 否則它就是一支「整份名單匯出」API |
| 🔴 最多回 **5 筆** | 同上;要找特定人 5 筆夠了 |
| 🔴 只回 **active**(已開通)使用者 | pending / disabled 的存在不該外洩 |
| 🔴 只回 **顯示名稱 + 截斷識別碼**,**絕不回 email** | L1b 第 14 條:email 不得顯示在任何頁面 |
| 🔴 只有該專案的 **owner** 能搜 | 不是登入就能搜 |

### 3.3 補上「ADMIN 都看得到」的守門測試

- admin **非成員**開 private 專案 → 200(不是 404)
- admin 的首頁清單**含**別人的 private 專案
- 一般使用者非成員 → 維持 404(不是 403)

## 4. 對現有資料的影響

🟢 **不動。** 不加欄位、不改既有列;`ProjectMember` 與 `visibility` 都已存在,
本任務只是讓人在畫面上操作它們。**無 migration。**

## 5. 驗收標準

1. owner 在專案頁可切換可見性,並看到成員清單。
2. owner 可用名字搜到人並加為 viewer / maintainer;可移除成員。
3. 🔴 非 owner(含 maintainer)**看不到**這個區塊,也打不動那些端點。
4. 🔴 搜尋:空白 q 不列全部、最多 5 筆、不含 email、只含 active。
5. 🔴 admin 看得到別人的 private 專案(**新測試**);一般使用者仍是 404。
6. 加人 / 移除 / 改可見性都留稽核。
7. 全套測試綠。

## 6. 明確不做

- 不做「以 email 邀請」(業務庫不存 email,且 L1b 禁止顯示)
- 不做外部分享連結(平台是內網、身分一律走 SSO)
- 不動 owner 轉移(API 已有 `project.transfer_owner`,介面另立任務)
