upload-program 介面導覽(給 UI 設計)

建立日期: 2026-07-29 10:10 最後更新: 2026-07-29 11:40 版本: v1.1 對象: UI / 視覺設計 目的: 讓你不用讀程式碼就知道:這個系統有哪些頁面、每頁長什麼、樣式住在哪裡、 哪些東西可以放手改、哪些是紅線不能碰。

1. 這是什麼系統

公司內部的開發者程式分享平台(可以想成「簡易版 GitHub」): 用公司帳號登入 → 建立專案 → 上傳原始碼/執行檔/文件 → 以版本發布 → 其他人瀏覽、搜尋、下載。

  • 正式網址:https://catsapp.sporton.com.tw/upload/(需公司帳號,首次登入後要請管理員開通)
  • 使用情境:內部工程師,桌面瀏覽器為主;頁面已做基本 RWD 但未特別為手機優化

2. 技術形態(這決定了你能怎麼做設計)

事實 對設計的意義
伺服器端算繪(Jinja2 模板),全站幾乎零 JS(只有上傳頁有一支進度條 JS) 沒有前端框架、沒有元件庫;改的是 HTML 模板 + 一支 CSS
樣式全部集中在一個檔案:app/static/app.css(約 260 行) 你的主戰場。目前是工程師寫的「能看」等級,全面美化空間很大
模板在 app/templates/(9 個 .html,Jinja2 語法) 版型骨架是 base.html(導航列 + 主內容區)
🔴 CSP 禁止 inline style / inline script <style> 標籤和 style="" 屬性一律無效,樣式只能寫進 app.css;JS 只能是外部檔案
🔴 禁止任何外部資源(CDN 字型、圖示庫、外部圖片都會被瀏覽器擋下) Google Fonts、Font Awesome 之類不能用;要自訂字型/圖示得把檔案放進 app/static/ 自行託管
🔴 只做淺色(light)主題(開發規範明定,禁 dark mode 與自動切換) 配色以白底深字為基準

目前的視覺基調(現況,可全面重定義):系統字體堆疊、白底、藍色連結、 灰階邊框卡片、少量 badge 與按鈕。CSS 變數已集中在 :root(--fg、--link、 --line 等),換色盤從那裡下手最省力。

3. 頁面清單(共 10 個畫面)

3.1 首頁 /upload/

  • 未登入:落地說明頁——系統簡介一段 + 「請先登入」提示。這是訪客的第一印象
  • 已登入:專案卡片列表(名稱、短名代碼、摘要、標籤)、頂部搜尋框、標籤篩選、分頁
  • 導航列(所有頁面共用):站名、搜尋框、「建立專案」「管理」(管理員才有)、使用者名、帳號設定、登入/登出

3.2 專案頁 /upload/projects/{slug}

本站最重要的一頁。最新版本置頂(產品決策:來的人十之八九是要下載最新版): - 最新版本區:版本號、發布說明、檔案列表(每個檔案:檔名、大小、SHA-256 校驗碼、掃毒狀態「未掃描」標示、下載按鈕、固定連結) - 其下才是專案資訊(擁有者、可見性、容量用量、標籤)與「版本歷史」入口

3.3 版本歷史 /upload/projects/{slug}/releases

所有版本的摺疊列表(原生 <details> 展開/收合,最新版預設展開),每版內含檔案清單與下載;分頁。

3.4 建立專案 /upload/projects/new、建立版本 /upload/projects/{slug}/releases/new

單欄直式表單(短名、名稱、摘要、可見性 / 版本號、說明)。驗證失敗會回到表單顯示錯誤訊息(紅框提示區)。

3.5 上傳頁 /upload/releases/{id}/upload

全站唯一有互動 JS 的頁:選檔 → 上傳進度條 → 已上傳檔案列表 → 「發布」按鈕。

3.6 待開通頁 /upload/pending

新使用者登入後的第一頁。核心元素是使用者自己的識別碼(一串 UUID),設計上要讓「複製這串給管理員」這個動作極其明顯——這是整個開通流程的樞紐,不是裝飾。

3.7 管理後台 /upload/admin/users、/upload/admin/audit

  • 使用者管理:待開通清單(一鍵開通按鈕)、其他帳號(停用/重新啟用);清單只有 UUID 沒有姓名(隱私規範,頁面上有說明文字解釋原因——這段文案是功能的一部分)
  • 稽核紀錄:操作流水(動作、時間、操作者、目標),動作類型篩選、分頁

3.8 錯誤頁(404 / 403 / 503 共用版型)

大字狀態碼、訊息、路徑與追蹤碼(給使用者回報用)。繼承導航列,讓人有路回首頁。

4. 你可以放手做的

  • app/static/app.css 全面重寫:色盤、字級階層、間距系統、卡片、按鈕、表單、badge、表格
  • 模板的 HTML 結構調整(加 class、換語意標籤、調整區塊順序)——見 §5 的但書
  • 自託管字型/SVG 圖示(檔案放 app/static/)
  • Logo / 站名視覺

5. 紅線與但書(碰之前先說)

紅線 原因
不能引入任何外部資源(CDN/外連圖片/第三方字型服務) 安全政策(CSP),瀏覽器會直接擋,不是規勸
不能用 inline style / <style> 標籤 同上
不能做深色模式 開發規範明定 light only
頁面內所有連結由模板的 url() 函式產生,不能手寫路徑 部署在子路徑下,手寫必 404
下載按鈕、SHA-256、「未掃描」標示不能弱化或藏起來 本站散布可執行檔,這三樣是安全告知義務
待開通頁的識別碼、管理後台的「為什麼沒有名字」說明文案 是功能不是裝飾,可以重排版但不能刪

但書:HTML 結構有 300+ 條自動化測試釘著行為(連結格式、內容出現與否、展開狀態等)。 結構改動不用怕,但改完要跑測試——流程是:你出設計(Figma / 標註圖 / 直接改 CSS 都行) → 我們套用並跑測試 → 有衝突的地方回來對。純 app.css 的改動幾乎不會撞測試, 是最安全的起點。

6. 上手方式

  1. 要帳號:登入 https://catsapp.sporton.com.tw/upload/ 一次,把待開通頁顯示的識別碼給 Benny 開通
  2. 逛一輪 §3 的十個畫面(建議實際走完:建專案 → 建版本 → 傳檔 → 發布 → 下載)
  3. 樣式檔:repo 的 app/static/app.css;模板:app/templates/*.html
  4. 產出交給 Benny:Figma 連結、標註圖、或直接改好的 app.css 都收
