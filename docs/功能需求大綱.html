upload-program 功能需求大綱

建立日期: 2026-07-26 00:15 最後更新: 2026-08-04 10:30 版本: v3.15

本文把「簡易型 GitHub」拆成可驗收的功能項,是後續所有任務的需求來源。 範圍界線與里程碑見 開發計畫書.md;技術設計見 設計_MVP.md; 任務追蹤見 任務表.md。 需求變更不直接改程式——先改本文與任務表(憲法第一條 4)。

0. 一句話定義

公司內部的開發者程式分享平台:登入後建立專案,在專案內上傳原始碼、執行檔、程式文件, 以版本為單位發布,同事可以瀏覽、搜尋、下載。

做的是「有版本管理的程式發布倉庫」,不是分散式版本控制系統。

1. 使用者角色

角色 定義 能做什麼
訪客 未登入 只能被導向登入頁,看不到任何內容
待開通使用者 首登建立,零角色(pending) 只能看到自己的身分與「請找管理員開通」的指引
一般使用者 已開通(active) 建立自己的專案;瀏覽/搜尋/下載所有 internal 專案
專案 viewer 被加入專案的成員 讀取與下載該專案(含 private)
專案 maintainer 被加入專案的成員 viewer 權限 + 建版本、上傳檔案、發布
專案 owner 專案建立者 maintainer 權限 + 改專案設定、管成員、刪除專案
平台管理員 platform_role=admin 開通/停用帳號、指派平台角色;可見全部專案

權限原則:deny-by-default。 身分由 Keycloak 認證,但「能做什麼」完全由本平台自己決定, 不碰 Keycloak 的角色設定。

2. 主要使用情境

# 情境 流程
U1 第一次使用 開站 → 導向 SSO 登入 → 回站後看到「待開通」指引 → 管理員開通 → 可用
U2 發布一個工具 建立專案 → 建立版本 v1.0.0 → 上傳執行檔 + 原始碼 + 使用說明 → 發布
U3 找別人的工具來用 搜尋關鍵字 → 開專案 → 看版本列表 → 下載執行檔 → 用 SHA-256 校驗
U4 發新版 開既有專案 → 建立版本 v1.1.0 → 上傳新檔 → 發布(舊版仍在,可回頭下載)
U5 內部限定的工具 建專案時設 private → 加入指定同事為成員 → 只有成員找得到、下得到

F17 的級距設計(2026-07-26 定案):

級距 上限 適用 誰能改
standard(預設) 2 GB 一般員工開發的小工具——約可容納 25 個一般版本 —
extended(需申請) 10 GB 帶 runtime 或多平台安裝包的大型專案 平台管理員
  • 為什麼預設取 2 GB 而非 5 GB: 上限調高比調低容易。調低要面對已經超標的既有專案, 調高只是改一個數字。先收緊、按需放寬,是風險較低的方向。
  • MVP 的「申請」怎麼走: 管理員直接調整專案級距,申請本身走線下(口頭/郵件)。 站內申請單(提交 → 審核 → 通知)是獨立功能,列 P2(F18)。
  • 超過上限時:回 413,錯誤訊息要指出目前級距、已用量與「可申請擴充」的指引, 不能只丟一句 Payload Too Large。

可見性規則

  • internal(預設):所有已開通使用者可讀、可下載
  • private:僅成員可讀;對非成員一律回 404,不洩漏該專案是否存在

F38「先預留」預留了什麼(2026-07-26 定案):

已預留 現況
artifacts.scan_status 欄位與 not_scanned / clean / infected 三態 ✅ 已存在,不必再改 schema
下載回應的 X-Artifact-Scan-Status 標頭 ✅ 已存在
上傳完成後的掛載點(upload_status 轉 ready 之處) ✅ 位置明確,屆時在該處送出掃描工作
尚缺 背景工作機制(佇列/worker)、掃描結果回寫 API、infected 時是否封鎖下載的政策

未接掃毒期間的誠實義務: scan_status 一律維持 not_scanned 並隨下載回傳, 不得因為「是內部平台」就把未掃描說成安全。

為什麼 F32/F35 是 P0 而不是「加分項」: 這是一個散布可執行檔的平台。 若讓上傳內容以 HTML/JS 在本服務網域被瀏覽器執行,等於自己開一個 XSS 給全公司。

T47 已於 2026-07-27 完成:規則是路徑 AND Accept 兩個條件都成立才回 HTML, /v1/* 與機器端點一律維持 problem+json(詳見 設計_MVP.md §4.1)。

Q7 我做的兩個補充判斷,若不同意請糾正:

  1. 「50~100M」我取上限 100 MB——執行檔動輒數十 MB,取 50 MB 容易卡住合理用途。
