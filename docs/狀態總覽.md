## 3. v0.3.2:這一版有什麼(**待發**)

| 任務 | 內容 | 資料影響 |

| **T137** | 「說明」類別接受 `.7z`(zip 因 docx 早就進得來,擋 7z 站不住腳) | 🟢 不動 |

換版前必須確認。🔴 症狀是**上限仍是 100 MB 而沒有任何錯誤訊息**。

## 4. 曾經卡住發版的那件事:已解除

2026-08-26 的 v1.0 把「CI Trivy 紅燈(openssl CVE-2026-14456)」列為**唯一阻塞發版**的事。
**已解除**,經過如下:

| 時間 | 事情 |
|---|---|
| 2026-08-26(T127) | Trivy 紅;試著在 runtime stage 自己升 openssl → `deb.debian.org` **connection timed out**;回退,備妥申請書 #11 |
| 2026-08-27(T102) | 改為 `apt-get upgrade -y` **全量升級**,並保留 T127 最貴的那一課:**驗證不相信離開碼** —— 判準是「升級後不得還有可升級的套件」(`apt-get -s upgrade` 的 `Inst` 計數必須為 0),不必維護 CVE 清單。**CI run #249 起 Trivy 綠** |
| 2026-08-31 | v0.3.0 發出並上線 |
| 2026-09-07 | PR #39 的 CI 全綠(663 passed、Trivy 零 HIGH) |

⚠ **誠實揭露一個我方沒有證據的缺口:** T102 的全量升級能成功,代表 CI 的 apt
**實際上連得到套件庫** —— 而 T127 當天量到的是 timeout。中間是平台側開通了、
還是當天的暫時性故障,**我方沒有證據,不臆測**。
🔴 **因此 #11 申請書仍未送出、仍留在索引裡**:那條路現在通,不等於它被保證。

📌 T127 挖出的那一課與這件事的成敗無關,值得單獨留著:
**`apt-get update` 抓不到索引時只印 `W:`,exit code 仍是 0** ——
`&&` 鏈只證明「每個指令都自稱成功」,不證明「事情做到了」。
對「取得外部資源」的步驟必須自己驗結果。

## 6. 發版步驟(v0.3.1 已照此走完;v0.3.2 同一套)

1. 合併 T133–T136 的 PR 到 `main`
2. 🔴 **打 tag 之前**先在 `main` 上確認 `APP_VERSION == "0.3.1"`
   (v0.2.4 事故:tag 指到了 `APP_VERSION` 還是舊值的 commit,而 CI 照樣綠、
   錯的 image 照樣推上 GHCR)
3. 打 `v0.3.1` tag(🔴 我方 tag push 得 403,**這是政策,不繞過** —— 由 Benny 推)
4. Release 頁貼四段內容(第八條 3:本版內容 / 資料影響 / 部署注意 / 測試)
5. VM 換版:
   - `.env` **無新增變數**、**不需跑 migration**
   - 🔴 換版重建容器後**必須** `docker exec portal-gateway nginx -s reload`,否則 502
   - ⚠ 先 `docker login ghcr.io`(見 §5.1)
6. 換版後驗證:
   - `tools/smoke.sh --vm --expect v0.3.2`(v0.3.1 時用的是 `v0.3.1`)
   - 🖐 專案頁看到明顯的「建立新版本」按鈕;**用 viewer 帳號看不到它**
   - 🖐 `/admin/projects` 列得出專案與版本/檔案/容量;**先 `./backup.sh` 再試刪除**
   - 🖐 管理總覽:稽核保留期的待辦**不該出現**(cron 已掛、未到期)

### 🔴 回滾的代價

**v0.3.1 → v0.3.0:退回舊 image 即可,無資料代價**(本版無 migration)。
⚠ 但**再往下退到 0.2.x 仍有 v0.3.0 的代價**:退 `0010` 會把待審版本一律當回草稿、
退回理由整欄消失;退 `0011` 會失去全部專案留言(runbook §B)。

## 7. 已知的營運限制(不是缺陷,是取捨)

1. 🔴 **平台沒有任何通知管道。** 作者送審後、專案被留言後,對方都不會收到提醒。
   審核靠管理員**主動看**管理總覽的待辦區。若實際運作上沒人天天看後台,
   審核制度會製造比它解決的更多問題 —— **這是要評估的營運現實,不是技術問題**。
   ⚠ `MAIL_ENABLED` 即使打開也只寄「有人回報問題」給管理員(T99),
   **不包含送審與留言**。
2. **掃毒尚未接上**,每個檔案誠實標示 `not_scanned`(T46)。
3. **留言沒有分頁**,少的時候沒問題,多起來要加。**不預先做**,但記在這裡。
4. **requirements 仍是相容區間不是 lock 檔** —— 建置不可重現(T82 遺留)。
5. **`/admin/projects` 的刪除沒有還原路徑**,也沒有「軟刪除」。
   確認方式是輸入短名(T134 A 案),那是唯一的煞車。
