## 1. 目標與範圍

### 1.1 產品目標

公司內部的**開發者程式分享平台**——「簡易型 GitHub」。開發者登入後:

1. **建立專案**(一個程式/工具 = 一個專案)
2. **開啟專案**後上傳三類內容:**原始碼**、**執行檔**、**程式文件**
3. 以**版本**為單位發布,他人可瀏覽、搜尋、下載

### 1.2 明確不做(MVP 範圍界線)

| 不做 | 理由 |
|---|---|
| git 協定(`git clone` / `push`)、commit 圖、diff | GitHub 的核心難點;本專案以「版本化的檔案集」取代 |
| Pull Request / code review / issue 追蹤 | 第二期再議 |
| 線上編輯、CI 建置 | 上傳既有產物即可 |
| 外網公開 | 內部平台,登入才可見 |

> 一句話界線:**做的是「有版本管理的程式發布倉庫」,不是分散式版本控制系統。**

### 1.3 非功能目標

| 面向 | 目標 |
|---|---|
| 安全 | 散布可執行檔的平台——判型、雜湊、強制 attachment 下載為不可退讓項 |
| 可用 | `/health` 60 秒內綠;換版不中斷既有請求(SIGTERM 30 秒優雅關閉) |
| 規約 | 通過 Cats 接入指南 §11 的 Definition of Done 全部檢查項 |
| 可維運 | 備份**且演練過還原**;migration 可雙向回滾 |

## 2. 系統架構

```
                        內網使用者
                            │ HTTPS 443
                  ┌─────────▼──────────┐
                  │   portal-gateway   │  全 VM 唯一持 80/443,依路徑前綴分流
                  └─────────┬──────────┘
                    external network: cats-edge
                            │  /«PREFIX»/(前綴會被剝掉)
        ┌───────────────────▼────────────────────┐
        │  upload-program stack                  │
        │  ┌──────────────────────────────────┐  │
        │  │ svc:8080(對外容器,FastAPI)     │  │  ← 只有它上 cats-edge
        │  └────────┬──────────────┬──────────┘  │
        │           │ backend      │ backend     │
        │  ┌────────▼───────┐ ┌────▼──────────┐  │
        │  │ db(PostgreSQL)│ │ minio(S3 相容)│  │  ← 不曝 port、不上 cats-edge
        │  │ volume: pgdata │ │ volume: data  │  │
        │  └────────────────┘ └───────────────┘  │
        └────────────────────────────────────────┘
                            │
                    ┌───────▼────────┐
                    │ Keycloak(IdP) │  只驗 token,不自建帳號
                    └────────────────┘
```
<!--SVG:architecture-->

**兩個由拓撲推導出的關鍵決定:**

1. **瀏覽器不直連 MinIO**——它在 `backend` 網路、不曝 port,且全 VM 只有 gateway 持 443。
   因此**上傳與下載一律由 svc 串流轉送**,不用 presigned 直傳。
2. **服務掛在子路徑且前綴被剝掉**——路由註冊在根路徑,只用 `root_path` 讓 OpenAPI 正確;
   對外絕對網址(OIDC redirect、cookie path)一律從設定組出,不從 request 推導。

## 3. 里程碑

| 里程碑 | 目標 | 出場條件(Exit Criteria) |
|---|---|---|
| **M1 規則與計畫** | 憲法、計畫書、任務表、設計文件到位 | 四份文件皆有版本歷史;md + HTML 並存 |
| **M2 骨架與規約落地** | 設定 / log / 錯誤格式 / DB / 模型 / 容器 / CI | `/health` 綠、CI 全綠、Trivy 無 high|critical |
| **M3 身分接入** | OIDC PKCE、JWKS、待開通、single logout | 冒煙清單前 5 項通過(用測試帳號) |
| **M4 核心業務** | 專案 / 版本 / 成員 / 搜尋 | 權限矩陣測試全綠 |
| **M5 檔案** | 串流上傳、magic bytes、下載、配額 | 惡意檔案測試全綠;大檔實測通過 |
| **M6 接入 Cats** | 申請 client、路由 PR、驗收、備份還原演練 | 接入指南 §11 DoD 全數打勾 |
| **M7 前端** | 最小可用網頁介面 | 使用者不需 curl 即可完成上傳與下載 |

## 5. 回滾原則

| 層級 | 回滾方式 |
|---|---|
| 程式 | 改 compose 的 image tag 回舊版 → `docker compose up -d` → **reload portal-gateway** |
| 資料 | migration 的 `downgrade()`;🔴 級任務另需備份還原程序 |
| 路由 | 回退 cats-portal 的 gateway 設定 PR → `nginx -t` → `nginx -s reload` |
| 文件 | git revert;版本歷史保留錯誤紀錄,不抹除 |

**換版不動 DB**:正常升版只換 image tag,資料活在 named volume 裡。

## 7. 接入前的八個問題(接入指南 §10)

| # | 問題 | 本專案的答案 |
|---|---|---|
| 1 | 語言 / 框架? | Python 3.12 + FastAPI(gunicorn + UvicornWorker) |
| 2 | 容器內部 port? | **8080**,綁 `0.0.0.0` |
| 3 | 要不要自己的 DB?資料量級? | 要:PostgreSQL 16。metadata 量小(千筆級);檔案在 MinIO,初估數十 GB |
| 4 | 健康檢查路徑? | `/health`(liveness,不查 DB)+ `/ready`(查 DB / MinIO / JWKS) |
| 5 | **能不能在子路徑下運作?** | **能**。FastAPI `root_path` + 對外網址由設定組出;gateway 可**剝前綴** |
| 6 | 靜態檔由誰供應? | MVP 無靜態檔(純 API);M7 前端上線時再議 |
| 7 | 要存哪些使用者相關欄位? | **只有 `sub`**。無 email / 姓名 / 密碼——不觸及個資紅線 |
| 8 | 路徑前綴偏好? | `/upload/`(最終由平台方定) |

> 第 5 題有一處要向 portal 確認:SSO 契約 §4.1 寫 redirect URI 固定為
> `https://<hostname>/oidc/callback/`,但在子路徑部署下實際會是
> `https://catsapp.sporton.com.tw/«PREFIX»/oidc/callback/`。申請 client 時需一併登記後者。

## 8. 已知風險

| 風險 | 影響 | 對策 |
|---|---|---|
| **未接掃毒** | 平台可能成為惡意執行檔散布管道 | 保留 `scan_status` 欄位並誠實標示 `not_scanned`;ClamAV 是否納入待決(T25) |
| 大檔經 svc 串流 | 佔用 worker 與 gateway 逾時 | multipart 串流(記憶體固定)、gateway 調 `client_max_body_size` 與逾時;必要時再議 presigned 專用路由 |
| 換版後 502 | 服務中斷 | 換版 runbook 強制 `disconnect → up → reload gateway`(T22) |
| MinIO 單點 | 檔案不可用 | 資料在 named volume;備份與還原演練列為 M6 出場條件(T23) |
| 事後補記的程式碼未經 TDD | 可能有未被測試釘住的行為 | 補齊測試並實際跑綠;未跑綠前任務不得標 ✅ |
